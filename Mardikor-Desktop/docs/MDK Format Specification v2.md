# MDK 文件格式规范 v2

版本：2 · 定稿日期：2026-11-16

状态：已定稿。规范定稿不表示当前 Mardikor 已实现全部要求。本规范独立定义 v2，不定义旧格式的读取、兼容或迁移。文中的“必须”“不得”为规范要求，“应”为有理由时可以偏离的建议，“可以”为可选能力。

现行应用文档以 [v1 规范](<MDK Format Specification v1.md>) 为基线；[迁移记录](MIGRATION.md) 描述应用技术栈迁移，不是 v1→v2 文件转换方案。CLI、使用指南和现行导出说明不构成 v2 要求。本文与同日定稿的 [设置目录](<MDK v2 Settings Reference.md>) 共同构成 v2 规范；完整工程示例见 [examples/v2](examples/v2/README.md)。

核心文件仍使用整数 `format_version = 2`，设置能力仍为 `mdk.settings-full@1`。后续勘误必须记录修订，且不得改变既有合法文件的解释；不兼容的语义变化按第 4.3、13 节修订相应版本。定稿变更记录见 [定稿说明](<MDK v2 Finalization.md>)。

## 1. 定位与边界

MDK 是携带 Markdown 正文、目录、资源和作品信息的可编辑工程容器。扩展名为 `.mdk`。文件整体是标准 ZIP，不包含自定义前缀、额外文件头或其他外部封装。

设计原则：

1. 正文的唯一权威来源是 UTF-8 Markdown 文件；不另存一份具有更高优先级的富文本 AST、HTML 或页面对象。
2. `default` 是共同的基础模型；`book`、`comic` 是其用途子集，只增加明文约束或缺省设置，不改变 Markdown 语法和资源引用含义。
3. 文件身份、目录位置、显示名称与磁盘路径分别表达。排序和改标题不要求改正文文件名。
4. 内容、展示设置、出版预设及本机状态分开。工程可编辑性不取决于是否能生成某种出版物。
5. 未知数据默认保留；不支持某种解释能力时必须报告，不得把丢失数据后的输出伪装成完整保存。
6. 规范不规定界面布局、默认文件名、保存按钮、自动保存间隔、编辑器实现或云服务协议。

本文定义基础容器、工程描述、目录、Markdown 基线、展示设置、出版预设和扩展机制。数学、脚注、批注锚定、完整历史和协作协议不在本规范中获得独立的标准语法；其状态见第 18 节。

## 2. 符合性与校验范围

实现必须说明自己支持的角色，不得仅因能够解压文件就宣称完整实现所有能力。

| 角色 | 最低职责 |
| --- | --- |
| 容器读取器 | 安全解析本规范的 ZIP 结构、名称、大小和校验数据；识别工程描述。 |
| 工程读取器 | 在容器读取器基础上解释核心控制文件、正文登记与目录结构，报告内容缺失及能力限制。 |
| 工程写入器 | 生成合法核心结构，保持一致快照，保留未修改内容和未知数据，执行安全发布。 |
| 基础预览器 | 实现第 8 节基线及第 7、10 节的基础阅读语义；不要求出版转换。 |
| 出版器 | 声明具体目标与支持的预设字段，验证并转换被选择的阅读内容；不要求支持所有出版格式。 |

一次校验必须区分以下结果：

- **容器校验**：ZIP 是否安全且结构完整。
- **核心校验**：工程描述、正文登记和目录关系是否符合 v2。
- **内容校验**：检查范围内的正文、资源和活动引用是否完整。
- **展示／出版校验**：具体设置、模式约束或所选出版预设是否可以正确执行。

校验报告是本次操作的输出，不是新增的包内控制文件。每个范围结果至少包含 `scope`、`status` 和问题列表；每个问题包含 `code`、`severity`、可读消息，以及能够确定的包内 `path`／字段 `field`。不能定位到具体文件的问题省略 `path`，不填写宿主绝对路径来冒充包内路径。

| 字段 | 取值／含义 |
| --- | --- |
| `scope` | `container`、`core`、`content`、`presentation`、`publication`、`portability`；最后一项用于宿主文件名／长度等限制。 |
| `status` | `pass`：范围内检查已完成且没有确定违规；`fail`：发现确定违规；`unverified`：因尚未识别容器、不支持、资源限额或尚未检查而不能完成判定。 |
| `severity` | `info`：说明；`warning`：不阻断该操作的限制；`error`：按第 14 节阻断该操作。`unverified` 的问题也可具有 `error` 严重度。 |
| `code` | 稳定的点分 ASCII 标识，标签匹配 `[a-z][a-z0-9-]*`，至少两个标签；`mdk.` 前缀保留给规范代码，应用代码使用自己的反向域名前缀。 |

最低通用代码为 `mdk.container.unrecognized`、`mdk.container.invalid`、`mdk.core.invalid`、`mdk.content.missing`、`mdk.settings.invalid`、`mdk.publication.invalid`、`mdk.capability.unsupported`、`mdk.limit.exceeded`、`mdk.path.nonportable`。通过 `scope`、`path`、`field` 和消息进一步定位，不把不同字段路径拼成不稳定的新代码。

起始签名不符合第 3.1 节时，必须报告 `scope = "container"`、`status = "unverified"`，问题代码为 `mdk.container.unrecognized`、严重度为 `error`。此时尚未进入 v2 容器内部校验，不因无法识别就断言原格式损坏。该 `error` 按第 14.2 节禁止正常 v2 打开、覆盖、完整交付及出版；只允许安全查看原始数据或另存原始字节，不自动剥离前缀。已识别的 ZIP 记录存在确定损坏时则报告容器 `fail` 及 `mdk.container.invalid`，两种情况不得混同。

同一范围汇总时，确定违规优先为 `fail`；没有确定违规但有未完成检查则为 `unverified`；否则为 `pass`。不支持的格式或超限本身不是“文件已损坏”的证据。各范围分别报告，内容通过不覆盖展示失败；是否允许打开、保存或出版仍由第 14 节决定。可移植性警告不自动使容器或核心校验失败。

“可保存的未完成工程”“基础内容可独立交付”“某个目标可出版”是不同状态；第 14 节规定它们的边界。

## 3. ZIP 容器

### 3.1 文件布局与快速识别

文件第 0 字节开始即为首个 ZIP 本地文件头，签名字节为 `50 4B 03 04`。不得在其前面放置 `mode`、自解压程序、填充或自定义魔数。

所有偏移按照 ZIP 的定义，以整个文件为相应单卷起点；不进行前缀修正。扩展名、MIME 声明或 ZIP 签名均不足以证明文件是合法 MDK v2，仍须验证容器约束及 `mdk.toml` 中的版本。

起始签名不符合时，报告 `mdk.container.unrecognized`，表示“无法识别为本规范的 v2 容器”，不是“已确认 ZIP 损坏”。这同样适用于任何带前缀的文件；读取器不必识别某个旧版本，不得扫描／剥离前缀后按正常 v2 打开。确有 ZIP 记录损坏时才报告相应损坏证据。相同扩展名或媒体类型不能代替版本和结构判定。

物理本地文件记录的前两项必须为：

1. `mimetype`：STORE，无 data descriptor，无本地 extra 字段。
2. `mdk.toml`：STORE，无 data descriptor，本地头直接给出 CRC 和大小；解压后最多 65,536 字节。前两项均不得使用 ZIP64 大小占位或 ZIP64 extra 字段；其他合法的 `mdk.toml` extra 字段不因此被禁止。

两项前面或之间不得插入目录条目。此顺序依据本地文件头在文件中的实际位置判定；中央目录顺序不参与判定。读取器可以只读取这两项获得候选类型、版本和模式，但此结果只是快速识别；正常打开或覆盖保存仍须完成相应校验。

`mimetype` 的全部内容为以下 ASCII 字节，无 BOM、换行、空格、结尾 NUL 或其他数据：

```text
application/vnd.mardikor.mdk+zip
```

`mdk.toml` 的大小上限用于保持快速识别成本可控。大段附加资料应放入正文或 `meta/` 扩展，不能通过在包外增加数据绕过限制。

上述 MIME 字符串是本规范规定的包内识别常量；本文不宣称已经完成其 IANA 注册。注册及外部协议中的媒体类型使用不替代这里的字节与版本检查。

### 3.2 ZIP 支持配置

ZIP 结构以 [PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) 为基础，并作以下限定：

| 项目 | v2 要求 |
| --- | --- |
| 卷 | 单卷；不支持分卷。 |
| 压缩 | 仅 STORE（0）及 DEFLATE（8）；容器读取器必须支持两者。 |
| ZIP64 | 允许单卷 ZIP64，包括为流式写入预先使用的合法 ZIP64 字段；前两项遵守第 3.1 节。已知普通字段足够时，写入器应避免不必要的 ZIP64。 |
| 加密 | 不使用 ZIP 加密或中央目录加密。 |
| 名称编码 | UTF-8，必须设置通用标志位 bit 11；不得使用本机代码页解释名称。 |
| 条目类型 | 仅普通文件与目录；不允许符号链接、硬链接、设备或重解析点条目。 |
| 目录条目 | 可以省略；存在时以 `/` 结尾、数据长度为 0，并满足路径规则。 |
| descriptor | 除前两项外，可以使用标准 data descriptor。 |
| ZIP 注释 | 允许，但不是工程元数据的权威来源，普通保存应保留。 |
| 附加数据 | 不允许自解压外壳、ZIP 结束记录及其注释之后的尾随数据，或未由受支持 ZIP 记录描述的额外数据。 |

容器读取器必须识别 ZIP64 元数据。读取器可以因明确的实现资源限额拒绝处理大工程，但必须区分“文件格式错误”“功能未实现”和“超出实现限额”。格式允许 ZIP64 不表示实现必须无限制地读取大文件。

本地头、descriptor、中央目录及 ZIP64 字段必须按 ZIP 规则一致。每个本地条目必须有对应的中央目录条目；禁止重复名称、文件与目录同名、普通文件作为父目录、记录或内容区间重叠。不得选择重复项中的第一项或最后一项继续保存。

比较名称时，先去掉目录条目末尾唯一的 `/`，再检查文件／目录冲突；检查范围包含隐式父目录。本地头与中央目录的文件名字节必须相同；额外字段不得提供另一个有效名称。descriptor 有无标准签名的形式都须能识别，按中央目录中的压缩大小定位并验证，不能在压缩数据里搜索签名猜测边界。STORE 条目的压缩与解压大小必须相等；目录条目统一使用 STORE、大小和 CRC 均为 0。强制 bit 11 及目录的这一存储形式是 MDK 的附加约束，不是对任意 ZIP 的要求。

读取条目内容时必须检查实际解压长度和 CRC。CRC 只用于损坏检测，不是来源认证。必须同时限制条目数量、实际输出总量、单项大小、内存、递归深度和处理时间，不能只相信头部声明值。

### 3.3 必需文件与推荐目录

```text
project.mdk                         # 整体为标准 ZIP
├── mimetype                        # 必需，物理首项
├── mdk.toml                        # 必需，物理第二项
├── contents.toml                   # 必需，正文登记与目录
├── settings.toml                   # 可选，文稿展示设置
├── publication.toml                # 可选，具名出版预设
├── markdown/                       # 正文；允许子目录
├── resources/                      # 图片、字体、音视频及附件
├── meta/                           # 持久扩展资料
└── state/                          # 可选，可重建的应用状态
```

最小工程只包含前三个文件。所有路径区分大小写。`resources/` 可以按 `image/`、`audio/`、`video/`、`font/` 等分类，但这些子目录名不决定文件类型，也不是合法性要求。

未列出的安全普通文件允许作为不透明附件存在。读取器不得因为不认识某种附件而删除它。各根目录的持久性要求见第 12 节。

## 4. 公共数据规则

### 4.1 文本与类型

核心 TOML 文件使用无 BOM 的 UTF-8 和 [TOML 1.0.0](https://toml.io/en/v1.0.0)；允许 LF 或 CRLF。核心 TOML 文件指 `mdk.toml`、`contents.toml`、`settings.toml` 和 `publication.toml`。损坏编码不得通过替换字符后静默保存。

正文使用 UTF-8，可带单个开头 BOM；该 BOM 不参与 Markdown 内容解释。这是 MDK 在交给 Markdown 解析器之前的预处理规则，不从解析器对 BOM 的偶然行为推断；仅忽略文件开头第一个 U+FEFF，其他位置保留。未修改正文须保留原始字节，包括 BOM、换行和末尾换行。

本节类型和缺省规则针对本规范已定义字段；未知字段按第 13 节保留，扩展字段由对应扩展定义。字段不进行类型强制转换：整数、浮点数、布尔值与字符串不同。声明为整数的字段不接受 `2.0`；已定义数值字段均须有限，禁止 NaN 和正负无穷。可选字段应省略，不用空字符串或空表替代不存在的路径、ID 或引用。

除明确允许空文本的字段外，字符串必须非空且不全为空白；不隐式 trim 后存回。时间如由扩展使用，其格式必须由该扩展明确定义，不能依赖宿主时区。

### 4.2 标识符

工程 ID、正文 ID、目录节点 ID 和出版预设 ID 都使用：

```text
^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$
```

比较区分大小写，不做 Unicode 归一化；建议写入器生成随机 UUID 或具有同等低碰撞概率的 ASCII 标识符。工程内正文、节点、预设各有独立 ID 命名空间；引用字段明确指定所引用的种类。

同一对象在保存、改名、移动或修改正文后保留 ID。删除对象后不得主动把旧 ID 分配给另一对象。复制创建新的正文、节点或预设时生成新 ID。原样复制整个文件不会自动改变工程身份；显式“派生为独立工程”应生成新的 `project_id`。

### 4.3 唯一的核心版本

`mdk.toml` 根字段 `format_version = 2` 定义本文全部核心控制文件的结构和语义。其他核心文件不再各自保存一个可能冲突的核心版本字段。

`format_version` 必须是 TOML 整数 2。缺失、类型错误或不支持的版本不能按 v2 正常编辑；可以只读查看或恢复副本。不得通过改写版本数字把未知结构变为已支持结构。

本文中缺省值是格式解释规则，不要求把缺省字段填入文件。第三方扩展独立版本化，不能改变已定义字段含义。

## 5. 工程描述：mdk.toml

### 5.1 最小内容

<!-- example: minimal/mdk.toml -->
```toml
format_version = 2
project_id = "d72477d4-93e7-4c2e-83d6-4d72e1961d9a"
```

缺省 `mode` 为 `default`。正文语法基线由格式版本决定，无需另写一个可以与之冲突的 Markdown 版本号。

### 5.2 字段

| 字段 | 类型 | 必需／缺省 | 含义 |
| --- | --- | --- | --- |
| `format_version` | integer | 必需，2 | 核心格式版本。 |
| `project_id` | ID string | 必需 | 工程身份；不是文件内容摘要或修改次数。 |
| `mode` | string | `default` | 仅 `default`、`book`、`comic`。 |
| `metadata` | table | 可选 | 作品信息。 |
| `features` | table | 可选 | 第 13 节的扩展能力声明。 |
| `extensions` | table | 可选 | 以带引号的反向域名为键的扩展数据。 |

`metadata` 的已定义字段如下；均可省略，出现时必须满足类型要求：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `title` | string | 作品标题；不由工程文件名反向覆盖。 |
| `creators` | string array | 按声明顺序排列的作者／创作者姓名；元素不得为空。 |
| `language` | string | 符合 [BCP 47 / RFC 5646](https://www.rfc-editor.org/rfc/rfc5646) 的语言标签，例如 `zh-CN`；不从应用语言推断并写回。 |
| `description` | string | 纯文本简介，允许空文本，不解释为 HTML。 |
| `publisher` | string | 出版者名称。 |
| `rights` | string | 版权或许可说明，允许空文本；不改变附件原有权利信息。 |
| `identifier` | string | 作品的绝对 URI 标识，例如 `urn:uuid:...`；与工程 ID 分开。 |
| `cover` | package path | 位于 `resources/` 的封面文件路径；不自动加入目录。 |

语言、标题、作者等缺省不影响基础工程合法性。出版器根据目标要求决定是否需要补齐。`metadata.identifier` 出现时必须符合 [RFC 3986 §4.3 的 absolute-URI 语法](https://www.rfc-editor.org/rfc/rfc3986#section-4.3)，即带 scheme、无片段的绝对 URI；相对路径、非法百分号转义和未经编码的空白不合法。MDK 另排除前缀匹配 `^[A-Za-z]:[\\/]` 的盘符路径（如 `C:/books/a`），不得把盘符当作 URI scheme 接受；UNC 和根相对路径也不合法。除这些明确排除的路径形式外，核心校验检查 URI 通用语法，不要求联网确认标识是否注册、存在或可解析；未知 scheme 本身不构成错误，标识的存在不授权访问资源。

`metadata.identifier` 非法时，报告 `scope = "core"`、`status = "fail"`、`code = "mdk.core.invalid"`、`severity = "error"`，定位 `path = "mdk.toml"`、`field = "metadata.identifier"`，并按第 14.2 节处理。出版器不得把非法值写入 `dc:identifier` 或 XMP，也不得以静默删除或替换绕过核心错误。字段省略仍合法；仅在目标要求它时，按第 11.3 节补齐或明确确认本次输出的合法值。

### 5.3 完整示例

<!-- example: book/mdk.toml -->
```toml
format_version = 2
project_id = "6ab75b43-a5cc-40de-9495-7b73a63f1984"
mode = "book"

[metadata]
title = "山路与归途"
creators = ["示例作者"]
language = "zh-CN"
description = "一部由 Markdown 文稿组成的示例作品。"
rights = "示例资料，仅用于格式演示。"
identifier = "urn:uuid:51d7c39d-09e2-460e-a94a-587b18f5c2a6"
cover = "resources/cover.svg"
```

## 6. 正文登记与目录：contents.toml

### 6.1 两种对象

`documents` 登记正文文件，`nodes` 表达阅读目录。一个正文可以被零个、一个或多个目录节点引用。`kind = "document"` 称为正文节点，`kind = "group"` 称为分组节点；正文节点不是文件的另一份副本。目录节点不能直接指向图片、PDF 或其他非 Markdown 附件。

`contents.toml` 可以为空文件；下列显式写法与之等价：

<!-- example: minimal/contents.toml -->
```toml
documents = []
nodes = []
```

两字段存在时必须是表数组。根级另允许可选的 `extensions` 命名空间表，缺省为空，规则同第 13 节。上述空文件等价性只针对已定义字段的解释；含未知字段或扩展的文件还具有必须保留的数据，不能被空文件替换。TOML 数组的物理排列顺序不决定阅读顺序。`contents.toml` 不定义模式、作品级信息、正文样式或出版配置。

### 6.2 documents

| 字段 | 类型 | 必需 | 含义 |
| --- | --- | --- | --- |
| `id` | ID string | 是 | 正文文件的稳定身份。 |
| `path` | package path | 是 | 必须位于 `markdown/` 下，以小写 `.md` 结尾；允许子目录。 |
| `title` | string | 否 | 此正文的缺省显示名，不等于第一行标题。 |
| `extensions` | table | 否 | 正文对象的命名空间扩展。 |

规则：

1. 正文 ID 和登记路径分别唯一。相同路径不能登记为两个不同正文 ID；重复展示通过多个节点引用同一个正文 ID 实现。
2. 文件改名或移动时只改变 `path`，保留正文 ID，并同步已知路径引用。复制成独立正文时必须同时使用新 ID 和新路径。
3. 路径满足语法但目标缺失时，正文登记仍可作为未完成工程保存，报告内容缺失；不得自动创建空文件替代。
4. 登记但没有节点引用的正文是未编排正文，必须保留，不自动加入阅读顺序。
5. 未登记的 `markdown/*.md` 及其子目录文件也允许作为草稿存在并须保留。需要被核心目录或以正文 ID 为目标的扩展引用时，必须先登记。核心正文类型以 `markdown/` 下小写 `.md` 文件为界；其他位置或大写扩展名的文件是附件，不能仅凭后缀猜测为另一份核心正文。
6. 正文显示名取 `documents.title`；缺省时取路径末段去掉 `.md` 的结果；若结果为空或全为空白，则使用未去掉后缀的原始路径末段，例如 `.md` 仍显示为 `.md`。正文节点的完整回退链是 `nodes.title` → `documents.title` → 上述文件名规则。分组节点必须有自己的 title，不参加此回退。不读取第一行标题替换结构数据，也不生成空导航标签。

### 6.3 nodes

| 字段 | 类型 | 必需／缺省 | 含义 |
| --- | --- | --- | --- |
| `id` | ID string | 必需 | 目录节点身份，与正文 ID 分开。 |
| `kind` | string | 必需 | `document` 或 `group`。 |
| `parent` | node ID | 可选 | 省略时为根节点；不得使用空字符串作为根。 |
| `order` | integer | 必需 | 1–2,147,483,647 的同级顺序键。 |
| `document` | document ID | 条件必需 | `kind = "document"` 时必需；分组节点禁止提供。 |
| `title` | string | 条件必需 | 分组节点必需；正文节点可省略并使用正文显示名。 |
| `extensions` | table | 可选 | 节点对象的命名空间扩展。 |

节点不再保存 `path` 或点分 `position`；它们不是这份结构的第二个权威来源。

树规则：

1. 节点 ID 唯一。`parent` 必须指向存在的节点，不能指向自己，整个关系必须无环且最终到达根。
2. 分组节点和正文节点都可以有子节点；一个节点只有一个父节点。禁止凭空生成没有 ID 的隐式父分组。
3. 同一父节点下 `order` 唯一；所有根节点视为同一组。顺序键可以不连续。重复顺序键是结构错误，不按 TOML 数组顺序或 ID 兜底。
4. `document` 必须引用已登记正文 ID。没有登记对象属于结构错误；有登记但文件缺失属于内容缺失，两者不能混同。
5. 遍历时先按同级 `order` 升序，再按父节点在前的深度优先顺序遍历，得到唯一目录顺序。过滤其中的分组节点得到阅读序列。
6. 正文节点先显示自身正文，再按遍历顺序显示其后代正文节点的正文；分组节点不占正文展示单元。空分组节点合法。
7. 显示编号由根到当前节点的各级同级排序序号（从 1 起）用 `.` 连接构成，所有分组节点和正文节点都计入，不随视图过滤改变。例如根节点序号 1 下的第二个子节点为 `1.2`；不直接显示 `order = 100` 为第 100 章。根深度为 1，子节点深度递增 1。编号不写回 Markdown，也不作为稳定引用。
8. 格式不设固定深度上限；实现必须防止栈溢出并声明深度限额。超限时报告实现限制，不得截断目录后保存为完整工程。
9. 移动节点时保留其 ID 和后代相对关系。通常只更新被移动节点的 `parent`、`order`，必要时重排同级顺序键；不要求改写全部后代。

整数顺序键和必要时重排是有意采用的单快照模型，不提供并发协作排序协议。写入器可以预留间隔，例如 10、20、30；相邻键无可用整数时，将最终同级序列重排为 1…N，或另一组保序的合法唯一整数，一次提交完整结果。保持未移动节点之间的相对顺序、全部节点 ID 和对象扩展关联，不重排后代的同级键。N 超出字段可表示范围或实现无法完成重排时，操作失败并保留原快照，不能写出重复键。

### 6.4 示例

<!-- example: book/contents.toml -->
```toml
[[documents]]
id = "doc-intro"
path = "markdown/intro.md"
title = "前言"

[[documents]]
id = "doc-road"
path = "markdown/road.md"
title = "山路"

[[documents]]
id = "doc-home"
path = "markdown/home.md"
title = "归途"

[[nodes]]
id = "node-intro"
kind = "document"
order = 10
document = "doc-intro"

[[nodes]]
id = "part-one"
kind = "group"
order = 20
title = "第一部"

[[nodes]]
id = "node-road"
kind = "document"
parent = "part-one"
order = 10
document = "doc-road"

[[nodes]]
id = "node-home"
kind = "document"
parent = "part-one"
order = 20
document = "doc-home"

[[nodes]]
id = "node-intro-again"
kind = "document"
order = 30
document = "doc-intro"
title = "附录：再读前言"
```

阅读序列为 `node-intro`、`node-road`、`node-home`、`node-intro-again`。最后一项复用 `intro.md`，拥有自己的目录标题和节点身份；编辑前言正文会影响两次出现。

## 7. 模式与共同阅读模型

`mode` 只取自 `mdk.toml`，不得在 ZIP 外、ZIP 注释或其他核心文件中再设置一个有效 `mode`。

| `mode` | 用途 | 本规范的附加内容限制 |
| --- | --- | --- |
| `default` | 通用 Markdown 工程 | 无。 |
| `book` | 长篇文稿与章节阅读 | 无；提供目录和编号缺省设置。 |
| `comic` | 图文展示单元与并排阅读 | 无；通过设置目录提供逐文稿预览的缺省设置。 |

本规范不凭名称推导“书籍只能是文字”“漫画必须每篇一图”等要求。今后版本若增加模式约束，必须明确列出并保持为基础模型的子集。第三方预设通过扩展表达，不擅自分配新的核心 `mode` 值。

| 模式相关的阅读缺省值 | `default` | `book` | `comic` | 支持层级 |
| --- | --- | --- | --- | --- |
| `reading.show_toc` | `false` | `true` | `false` | 基础 |
| `reading.chapter_numbering` | `false` | `true` | `false` | 基础 |
| `preview.layout` | `continuous` | `continuous` | `document` | 设置目录 |

其余核心阅读缺省值不随模式变化。基础预览器可以没有逐文稿视图，因此 `comic` 在基础实现中的缺省效果可以与 `default` 相同；必须报告未支持的补充展示能力，不能声称完整实现该效果。

三种模式的共同规则：

1. 实际阅读顺序由第 6 节决定。一个正文节点对应一个逻辑展示单元，即完整的一篇 Markdown。
2. 纯文字、空文稿或包含多张图片的文稿都合法。不得自动按图片数量拆分，也不得因选择 `comic` 而隐藏文字、表格或代码。
3. `spread = "double"` 缺省把阅读序列两两配对。配对后剩余的末个正文节点没有同组第二项时，单独显示在双页组的首项位置（`ltr` 为左、`rtl` 为右），不是放在前一正文节点所在侧。支持设置目录相应字段的实现还须应用 `reading.first_single = true`：第一个正文节点单独占一个单页展示框，并在双页展示区域中水平居中；不把它拉伸成双页宽度。从第二个正文节点开始配对，末项仍按上述首项位置放置。该字段缺省为 `false`；仅支持基础集合的预览器报告未支持的 `first_single` 后可按 `false` 临时预览，不得把含此要求的完整展示校验记为通过。分组节点不占位，重复正文节点各自占位。
4. `direction = "ltr"` 时前项在左，`rtl` 时前项在右；不反转目录，也不反转正文段落、字符或文字书写方向。
5. 并排预览不表示 Markdown 已有固定物理页。PDF 自动分页、EPUB 阅读器分页和固定页面排版分别由出版规则处理。
6. 显式设置优先于模式缺省值。任何合法 `book`/`comic` 工程只把 `mode` 改为 `default` 后，正文、ID、目录和资源均无须转换，仍须合法。
7. 模式切换不得隐式拆分、合并、栅格化或重写 Markdown。未知 `mode` 不按 `default` 猜测为合法；只读恢复并报告核心字段不支持。

## 8. Markdown 与标题链接

### 8.1 基线

所有 mode 使用 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)，仅采用 [GFM 0.29-gfm](https://github.github.com/gfm/) 的 Tables、Task list items、Strikethrough 三项扩展。GFM 文本的基础规则来自 CommonMark 0.29；MDK 的基础规则以 0.31.2 为准，上述三项仅增加对应语法。不采用 GFM 的 Autolinks 或 Disallowed Raw HTML；原始 HTML 按下一段处理。不自动启用裸网址链接化、智能标点、YAML front matter、脚注、数学、容器或 HTML 执行。

原始 HTML 仍按 CommonMark 识别其块／行内边界，但渲染时转义为可见文本，不执行标签、属性或脚本。普通代码块仅展示代码；语言名不授权执行程序。图片替代文本必须保留；表格、任务列表和其他内容不得因模式而消失。

文稿需要其他语法时，必须通过第 13 节声明对应版本的扩展。扩展不能把同一 `mode` 下的 Markdown 偷换为另一种正文格式。基础读取器始终可以提供源码；“显示源码”不等于“完整渲染已声明扩展”。

未修改 Markdown 必须按原始字节保留。可视化编辑器不能无损表达的构造应保留为不透明块或限制编辑；不得仅因打开、切换模式或保存其他文稿而重排整个文稿。

### 8.2 自动标题锚点

基线标题锚点按每个 Markdown 文件独立计算，ATX 与 Setext 标题一视同仁，包括被解析为标题的引用块／列表项内标题；按它们在源文稿中的出现顺序统一编号。代码块和原始 HTML 块中的标题形状文本不生成锚点。算法使用 Unicode 15.1 的字符分类和该版本 UAX #15 的 NFC 归一化；实现不得采用宿主区域的大小写规则。

1. 从标题的已解析行内内容提取可见文本：文本和代码内容保留，强调／删除线／链接只取内部文本，图片取替代文本，软／硬换行取一个空格，行内原始 HTML 取其可见源码。转义和字符引用按 Markdown 解析结果处理。
2. 文本做 NFC 归一化；仅 ASCII `A`–`Z` 转为小写，其他字符不做大小写转换。
3. Unicode `White_Space` 字符的连续区段替换为 `-`。保留 Unicode 通用类别 L、M、N 的字符以及 ASCII `_`、`-`，删除其他字符。
4. 连续 `-` 合并为一个，去掉首尾 `-`；空结果使用 `section`。添加固定前缀 `h-`。
5. 按正文顺序分配锚点。候选值若已使用，依次尝试追加 `-2`、`-3` 等，取第一个未被使用的值；检查整个已用集合，不只统计相同原标题。

例如三个依次出现的标题 `第一章`、`第一章`、`第一章-2` 对应 `h-第一章`、`h-第一章-2`、`h-第一章-2-2`。代码块中的 `#` 不生成锚点。图片、脚注等扩展自行生成的目标不得占用 `h-` 命名空间。

Markdown 中仍使用普通链接，例如 `[第一章](road.md#h-山路)`；不要求专用协议。锚点依赖标题和重复顺序，不承诺在修改标题或插入同名标题后仍保持稳定。编辑器应诊断并在可确定时同步已知链接，不得凭相似文本猜测为同一目标。

### 8.3 重复展示的链接目标

工程内链接首先定位正文文件，不以目录节点的显示名定位。把正文转换为单一阅读视图或出版物时：

- 目标为当前正文文件时，跳转至当前节点所展示的这一份正文。
- 目标为其他正文文件，且它在阅读序列中出现多次时，选择阅读序列中的第一次出现。
- 目标正文没有任何阅读节点时，工程内编辑器可以打开该文稿；出版器必须报告目标未纳入出版，不能静默把链接指向任意其他文稿。
- 出版器必须为重复出现的正文生成互不冲突的输出目标并改写链接；不把这些输出 ID 写回 Markdown。

核心语法暂不提供“跳到另一个正文的第二次出现”这种节点专属链接；有此需求应由独立扩展定义，不能改变普通相对链接含义。

## 9. 路径、资源与引用

### 9.1 包内路径

ZIP 名称、正文登记路径、封面路径和字体路径是工程根目录相对的字面路径，不是 URL，不做百分号解码。

1. 使用 `/` 分隔，不允许绝对路径、盘符或 UNC 形式；路径中不得出现反斜线、冒号或 Unicode Cc 控制字符（U+0000–U+001F、U+007F–U+009F）。
2. 不允许空路径、空路径段、`.`、`..`。文件名不以 `/` 结尾；目录条目以 `/` 结尾形成的末尾空段，是“不允许空路径段”的唯一例外；该 `/` 之前仍须有合法且非空的目录路径。
3. 路径区分大小写，按实际 Unicode 序列精确匹配。读取时不自动归一化、折叠大小写或合并名称。
4. 写入器新建名称必须使用 NFC，并应避免大小写或归一化后相同的名称；已有名称按原始序列保留。宿主不支持的名称作为可移植性问题报告，不自动改名或合并；包内访问仍遵守原始名称。
5. 解包前必须检查所有目标名称、已有路径、大小写／Unicode 冲突和实际目录边界。不得跟随符号链接或重解析点把内容写到目标目录之外，也不得静默覆盖冲突文件。

可移植性检查至少报告 Windows 保留设备名（如 CON、NUL、COM1，含扩展名及大小写变体）、尾部空格／点、目标宿主禁止的字符、大小写／Unicode 冲突和名称长度超限。这些宿主限制本身不改变 ZIP 内字面名称的格式合法性；无法安全映射时禁止直接解包到该宿主路径，可在包内浏览，或显式改名并同步引用。格式不另设统一的 260 字符等宿主路径上限，仍须遵守 ZIP 名称字节长度边界与实现限额。

含 Unicode 15.1 Bidi_Control 字符的名称作为伪装风险给出警告；文件选择、校验、删除确认及日志必须提供转义后的真实字符／路径，不能仅显示受双向控制影响的外观。这类字符不被自动删除，也不据此反转保存的名称。

### 9.2 Markdown URL 解析

1. 使用 Markdown 解析器取得活动链接／图片的目标，不在代码块、行内代码或普通示例文字中做正则替换。
2. 先区分 URI scheme、网络路径引用、相对路径、查询和片段。以 `//` 开头的网络路径引用不当作包内文件，基础配置禁止加载。
3. 包内 URL 相对于当前 Markdown 文件所在目录解析。允许 `.`、`..`，逐段解析后不得越过工程根目录。
4. 包内目标路径先拒绝字面反斜线和控制字符，再按 `/` 切分；各段只执行一次严格的 UTF-8 百分号解码。无效转义、无效 UTF-8，或解码后含 `/`、反斜线、冒号、Unicode Cc 控制字符时拒绝；解码出的点段仍须参与边界检查。
5. 包内 URL 不以 `/` 开头；非空路径不允许重复分隔符或末尾分隔符。空路径表示当前文件。查询和片段不参与文件名匹配。
6. 基础配置不定义包内查询参数的语义。含非空查询的本地引用可保留为源码，但在完整内容交付和出版前必须修正或由已声明扩展解释；不能只因文件存在就声称完整支持该链接。空查询与省略查询等效。
7. 指向第 6.2 节核心 Markdown 文件的非空片段按第 8.2 节验证：严格百分号解码一次后精确匹配，不把 `+` 当空格；不进行额外 Unicode 归一化。空片段与无片段都指向文件起点。未找到锚点属于内容缺失。对其他媒体的片段，只有实现支持其明确语义时才能验证，否则标记未验证，并阻止依赖该片段的完整交付／出版通过，除非显式选择有损转换。
8. 字面文件名里的 `%`、`#`、`?` 必须在 URL 中正确编码。例如 `resources/a#b.png` 对应引用中的 `a%23b.png`。不得二次解码 `%252e%252e`。

HTTP、HTTPS、mailto 导航链接允许保留；跟随链接必须由用户动作触发。外部 HTTP(S) 展示资源默认不加载，用户授权加载也不代表它已被打包。`file`、`javascript`、`vbscript`、`data` 及未获支持的其他 scheme 不得作为活动内容加载。

scheme 比较不区分 ASCII 大小写。取得目标时不得先交给会改写反斜线、补协议或二次解码的浏览器 URL 解析器；拒绝目标中的字面控制字符，包内路径严格按上述规则处理。附件链接可以保留和提取，但目标存在不等于实现支持展示它；图片引用无法解码时须报告未验证，不能仅以路径存在判定完整可渲染。

解析后的包内目标必须是普通文件；目录条目及隐式目录不能作为链接或图片目标。目标文件暂时缺失属于内容缺失；目标是目录则属于引用类型错误，不能把目录下某个文件自动当成目标。

### 9.3 资源管理

已知文件类型应结合内容识别，不能只相信扩展名。未知附件作为不透明字节保留，不要求能预览。不应仅为识别附件而执行文件。

正文引用、封面路径、设置及各出版预设中可解析的已知字体路径，以及已支持扩展所声明的依赖共同构成已知引用关系。引用维护不以当前开关或预设是否启用为限；字体集 ID 改名也要更新已知 @ 引用。重命名或移动文件时，必须更新受影响的已知引用；若未知或无法解析的配置可能依赖该路径而无法保护关联，应限制操作或生成用户明确选择的有损副本，不能静默断链。操作资格中的依赖检查范围另按第 14 节决定，不能用“本次出版没用到”豁免引用维护。

“没有发现引用”不是自动删除资源的依据。资源整理、去重、改名和删除是显式编辑操作，不是普通保存的隐含步骤。删除一个目录节点也不默认删除正文；删除正文登记不默认删除文件。

所有用作内容、封面、字体或其他持久依赖的路径都不得指向 `state/`。这是结构性隔离规则，防止排除状态时损坏正文。

## 10. 展示设置：settings.toml

### 10.1 内容与缺省值

此文件可省略或为空。只定义可随作品携带的正文样式和阅读展示，不保存窗口位置、工具栏状态、自动保存策略、输出路径或覆盖授权。

下表是基础支持集合。完整可选字段、类型、继承和关联约束见 [settings 最大支持目录](<MDK v2 Settings Reference.md>)，完整示例见 [settings.full.toml](examples/v2/settings.full.toml)。基础预览器必须支持下表；`@字体集ID` 属于补充能力。完整实现通过第 13 节的 `mdk.settings-full@1` 声明，不要求最小读取器承担全部排版功能。

设置目录是规范性组成部分，其标准能力版本为 `mdk.settings-full@1`；主规范界定基础集合，设置目录定义完整集合，两者随本规范一起修订，不另设 `settings` 的核心版本字段。仅支持基础集合的实现依第 13 节报告补充能力未支持并保留其数据；缺少文档或实现能力不使未知字段成为空设置。

作用域 S 是正文共享样式，适用于预览和声明支持的出版目标；R 是阅读编排、导航及视图附加信息，出版只采用明确映射的字段；V 是屏幕预览，不参与出版布局。出版预设的正文样式覆盖只允许 S 字段。

| 字段 | 类型／范围 | 缺省值 |
| --- | --- | --- |
| `body.font_family` | `serif`、`sans-serif`、`monospace` | `sans-serif` |
| `body.font` | `generic`、`resources/` 下的字体路径；补充能力另允许 `@字体集ID` | `generic`；路径值优先使用包内字体 |
| `body.font_size` | 有限正数，CSS px | 16 |
| `body.line_height` | 有限正数，字号倍数 | 1.7 |
| `body.paragraph_spacing` | 有限非负数，em | 0.8 |
| `body.text_color` | `#RRGGBB` | `#1f2933` |
| `body.background_color` | `#RRGGBB` | `#ffffff` |
| `body.link_color` | `#RRGGBB` | `#2563eb` |
| `preview.max_width` | 有限正数，CSS px | 720 |
| `reading.direction` | `ltr` 或 `rtl` | 所有模式为 `ltr` |
| `reading.spread` | `single` 或 `double` | 所有模式为 `single` |
| `reading.image_fit` | `contain`、`cover`、`width` | 所有模式为 `contain` |
| `reading.show_toc` | boolean | `book` 为 `true`，其他为 `false` |
| `reading.chapter_numbering` | boolean | `book` 为 `true`，其他为 `false` |
| `extensions` | table | 空 |

颜色十六进制字符比较不区分大小写，写入器推荐小写；基础颜色字段只接受不透明 `#RRGGBB`，不接受 alpha 通道或依赖宿主背景的透明色。设置目录中的局部背景 paint 类型另允许 `none`，但正文底色仍由 `body.background_color` 确定。`body.font`=`generic` 时使用 `body.font_family`；指定包内主字体时先用该字体，缺字再使用已声明后备链，最后使用通用字体族。基础实现没有补充后备链时，直接以通用字体族解决缺字。来源缺失／损坏和正常缺字必须区分，包内来源不可用时须报告，不得冒称已应用；`generic` 不承诺跨平台字形或分页一致。

`preview.max_width` 是单个正文显示框的最大外宽，不决定 PDF 纸张或 EPUB 固定页面尺寸；双栏时分别约束两个框。小屏幕可以使用更窄的可用宽度。`reading.image_fit` 只作用于图像区域：`contain` 完整缩放、`cover` 可裁切图像、`width` 按固有比例适配可用宽度并继续服从尺寸上限；不得用它裁去文字或整篇 Markdown。设置目录的 `images` 表明确图像框比例和尺寸约束；`frame_ratio = 0` 时使用固有比例，`cover` 与 `contain` 不产生比例差异导致的裁切。

`show_toc` 控制阅读导航的缺省可见性；`chapter_numbering` 使用第 6.3 节计算的节点编号作为视图标记。两者均不修改源标题，也不改变目录遍历。

解释优先级为：格式基础缺省值 → 当前 `mode` 的缺省值 → 显式合法设置。阅读器的无障碍或个人显示覆盖可以临时生效，但必须与工程设置分开，不能被隐式写回或用于出版。

### 10.2 示例

<!-- example: book/settings.toml -->
```toml
[body]
font_family = "serif"
font_size = 17
line_height = 1.8
paragraph_spacing = 0.8
text_color = "#1f2933"
background_color = "#ffffff"
link_color = "#2563eb"

[preview]
max_width = 760

[reading]
show_toc = true
chapter_numbering = true
direction = "ltr"
spread = "single"
image_fit = "contain"
```

### 10.3 错误与回退

TOML 语法或 UTF-8 错误时，整份文件暂停解释并使用模式与基础缺省值；合法 TOML 中单个字段错误时只回退该字段，表类型错误时回退该表的已知字段。未知字段不因未知而视为类型错误。

设置目录中的字段有明确关联关系时，按设置目录回退对应字段组，例如预览几何组、目录标题等级范围。未知能力、未实现字段与字段非法分别报告。

所有回退均为临时值，必须报告，不得自动修复文件。原文件未修改时，可以原样保留并保存其他内容。可解析设置允许局部修复：本次新增／修改字段及其受影响的关联约束必须合法，不得引入新错误；未触及且不受影响的原有错误按原值保留并继续报告。修改某字段的依赖也属于影响范围，不能借更改字体集 ID 留下新的悬空引用。展示错误不阻止保存正文或基础内容交付，但展示校验不能因此记为通过。

例如原有 toc 等级范围非法时，可独立修改 `body.font_size`；修改 toc 的任一等级则必须使整对范围合法。整份文件语法损坏时不执行结构化字段编辑；整份替换或重新生成文件必须通过已知设置校验，不能把局部修复规则用于无依据地丢弃或重建其他字段。

出版器使用正文样式时，必须验证其最终依赖的字段；不能拿预览器的临时回退冒充已确认的出版设置。出版预设中显式合法的覆盖值可以取代对应错误字段，未覆盖的错误依赖仍阻止该次出版。

上述覆盖只适用于可成功解析为 TOML 树的设置；整份 `settings` 的 UTF-8／TOML 语法损坏时不能确定其意图，须先修复，或由用户明确选择忽略它的有损出版副本。预设覆盖不能让正常出版默默使用临时缺省值。类型错误的表不等于空表：其中全部已知子字段视为错误，只有该次输出实际依赖的子字段均被合法覆盖后，才可消除该表对输出的阻断。

## 11. 出版预设：publication.toml

### 11.1 范围与结构

此文件可省略或为空。它提供出版配置交换，不能要求基础读取器具备 PDF 或 EPUB 生成能力。出版输出是独立产物，不替换正文和工程。

根字段 `presets` 是表数组，缺省为空；`default_preset` 可选，存在时必须指向本文件中的预设 ID；根 `extensions` 可选。默认预设只表示建议选择项，不能在打开工程时自动执行导出。

每个预设包含：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `id` | ID string | 必需，在全部预设中唯一。 |
| `name` | string | 可选，显示名称；缺省显示 ID。 |
| `format` | string | 必需，闭合枚举 `pdf` 或 `epub`。其他取值是该核心预设的配置错误；第三方目标在自身 `extensions` 命名空间定义独立配置，不扩展此枚举。 |
| `requires` | feature token array | 可选，执行此预设所需的扩展；第 13 节的 token 规则。 |
| `body` | table | 可选，覆盖第 10 节及设置目录的 `body` 字段。 |
| `paragraph`、`headings`、`links`、`inline_code`、`code`、`quote`、`lists`、`tasks`、`tables`、`images`、`thematic_break` | table | 可选，只覆盖设置目录标为 S 的字段；headings 分级及 `code.palette` 可按叶字段覆盖。 |
| `reading` | table | 可选，仅允许覆盖 S 字段 image_fit。 |
| `pdf` | table | PDF 预设中必需；EPUB 预设中禁止出现。 |
| `epub` | table | EPUB 预设中必需；PDF 预设中禁止出现。 |
| `extensions` | table | 可选，目标专属配置及实现扩展。 |

第三方出版目标的独立配置放在 `publication.toml` 根级 `extensions` 的对应命名空间中；配置结构、选择入口及默认选择由该扩展定义。它们不属于核心 `presets`，不参与核心预设 ID 的命名空间，也不由 `default_preset` 选择。未知目标按第 13 节保留，不自动执行；核心预设内的 `extensions` 仅增强该预设已有的 PDF／EPUB 目标，不改变 `format` 的含义。

出版使用第 6 节完整阅读序列，不自动纳入未编排正文、草稿、批注或其他附件。本规范不定义选择目录子集的字段。出版前必须有至少一个正文节点（`kind = "document"`），且该次序列的登记文件存在并满足内容校验；正文允许为空，空正文节点仍计入，只有分组节点的工程不具备出版正文。

自动目录及 EPUB 导航从完整 `nodes` 树及节点显示名生成，保留正文的重复出现。仅在派生导航中剪去完全没有正文节点后代的分组子树；空正文的正文节点仍保留。正文项链接到该次正文起点；其余分组节点为带子目录、不带正文链接的分组标签。这样不会生成 EPUB 禁止的无目标叶分组，也不删除源工程中的空分组节点。阅读视图的 `toc` 过滤、`chapter_numbering` 和 `numbering.format` 不改变出版导航，也不自动加入源码标题子目录。[EPUB 导航内容模型](https://www.w3.org/TR/2026/REC-epub-33-20260113/#sec-nav-def-model)

正文样式的优先级为：基础缺省值 → 工程显式设置 → 本预设显式覆盖。对象按叶字段覆盖，数组整体替换；先应用覆盖，再解析依赖与继承，标题等依赖 `body` 的缺省值须按最终生效的 `body` 计算。预设之间不继承。若某个已显式配置且必须参与输出的字段非法，不得用缺省值掩盖错误继续发布。

`font_sets` 只在 `settings` 登记；预设可引用工程字体集，不另建同名字体集。已知 R（阅读编排、导航及视图附加信息）／V（屏幕预览）字段不能写入正文样式覆盖表，例如 `links.visited_color`、`tables.overflow` 和 `reading.spread` 均属于正文样式覆盖通道的不适用字段错误。出版方向和配对使用目标表中的专用字段；未知字段仍按保留规则处理。使用高级设置的预设可以用 `requires` 要求 `mdk.settings-full@1`。

### 11.2 PDF 预设

以下字段位于必需的 `pdf` 表。`layout` 必须显式写入，其他字段可按表中规则缺省。应用创建预设时可以建议 `book`/`default` 使用 `flow`、`comic` 使用 `fixed`，但必须将选择写入预设，不能让后续模式切换改变预设的布局类型或字段合法性。

创建书籍预设时可以建议 `include_toc`=`true`、`chapter_break = "page"`，但采用建议必须写入预设。读取时不根据 `mode` 推断这些字段。仅切换 `mode`、保持元数据与显式设置不变时，核心出版预设的输出语义不改变；这不承诺不同出版引擎产生相同字节。

| 字段 | 类型／范围 | 缺省值与含义 |
| --- | --- | --- |
| `layout` | `flow` 或 `fixed` | 必需，无缺省值。 |
| `page_width` | 有限正数，mm | 210 |
| `page_height` | 有限正数，mm | 297 |
| `margin_top` / `margin_bottom` / `margin_left` / `margin_right` | 有限非负数，mm | 各 20 |
| `include_cover` | boolean | `false`；`true` 时必须有合法封面。 |
| `include_toc` | boolean | `false`，与 `mode` 无关。 |
| `chapter_break` | `none` 或 `page` | `none`，与 `mode` 无关；仅 `flow` 有效。 |

左右边距之和必须小于页面宽度，上下边距之和必须小于页面高度。尺寸与方向由宽高直接表达，不再设置可能与宽高冲突的 landscape 字段。正文 CSS px 与物理单位的换算采用 `1in = 96px = 25.4mm`。

`flow` 允许正文自动分页；`chapter_break = "page"` 在每个正文节点之前开始新页，若已经处于空白新页顶部则不额外插页。分组节点的存在本身不会强制产生正文页，可以进入目录。

`fixed` 使每个正文节点在扣除边距后的单个页面内完整排版；出现文字、表格或代码溢出时必须报告失败。图片可以按已声明适应方式缩放或裁切，但不得把整篇 Markdown 栅格化以规避布局限制。`fixed` 预设中显式提供 `chapter_break` 属于不适用字段错误。

`include_cover = true` 时生成独立的首张封面附加页，保持图片完整比例；`include_toc = true` 时生成自动目录页，位于封面之后，未生成封面时位于文档开头。目录所需页数由出版器决定；正文接在已生成的附加页之后。两个开关均为 `false` 时直接从正文开始，不自动增加封面或目录页。附加页不成为正文节点，不改变源目录。本规范不定义将两个正文节点合并成一张 PDF 纸的拼版；`reading.spread` 不自动触发 PDF 拼版。

PDF 输出以 PDF 1.7／ISO 32000-1:2008 为最低目标；可以生成更新版本，但不能只因生成 PDF 就宣称符合 PDF/A 等额外标准。所有实际用于文字的字体（包括由 `generic` 解析出的字体）必须嵌入，可对子集化后覆盖所用字形的字体进行嵌入。无法嵌入或没有嵌入权限时，该次出版失败，或由用户明确选择有损替代；纯图形内容无须添加无用字体。不得把 Markdown 正文文字转成路径或位图来规避字体要求；应提供与原文相符的 Unicode 文本映射以供提取。PDF 不设置关闭字体嵌入的核心开关。

### 11.3 EPUB 预设

以下字段位于必需的 `epub` 表。`layout` 必须显式写入；应用可以按 `mode` 建议初始布局，但它不是读取时推断布局的依据。

| 字段 | 类型／范围 | 缺省值与含义 |
| --- | --- | --- |
| `layout` | `reflowable` 或 `fixed` | 必需，无缺省值。 |
| `direction` | `ltr` 或 `rtl` | 使用工程有效的 `reading.direction`。 |
| `spread` | `single` 或 `double` | 使用工程有效的 `reading.spread`；仅 `fixed` 有效。 |
| `first_single` | boolean | 使用工程有效的 `reading.first_single`，缺省 `false`；仅 `fixed` 有效。 |
| `page_width` / `page_height` | 有限正数，CSS px | `fixed` 各为 800 / 1200；`reflowable` 不适用。 |
| `include_cover` | boolean | `false`；`true` 时必须有合法封面。 |
| `toc_in_spine` | boolean | `false`；是否把目录页加入线性阅读序列。 |
| `embed_font` | boolean | `reflowable` 为 `false`，`fixed` 为 `true`。 |

EPUB 输出必须符合第 19 节固定版本的 [EPUB 3.3](https://www.w3.org/TR/2026/REC-epub-33-20260113/) 要求，包括元数据、导航、资源清单和阅读顺序。必须有 `dc:title`、`dc:language`、`dc:identifier` 以及恰好一个 `dcterms:modified`。前三项缺失时须由作者补齐，或在本次出版中明确确认使用的值；不得从文件名、宿主语言、用户名或工程 ID 静默推导作品身份。

`dc:identifier` 的文本值取 `metadata.identifier`；`package` 的 `unique-identifier` 属性指向该元素的 XML ID，而不是直接填写 URI。`dcterms:modified` 使用本次产物生成时刻，UTC、秒精度，格式为 `YYYY-MM-DDThh:mm:ssZ`；不是源文件修改时间，不写回 MDK。可复现出版所需的固定时刻由明确的预设扩展规定，不能通过本机时区隐式改变。其他映射见第 11.6 节。

`toc_in_spine`=`false` 仍须生成必需的 EPUB 导航文档，只是不把它作为正文阅读序列中的目录页；`true` 时在附加封面之后、首篇正文之前加入目录页。`fixed` 的目录页过长时可拆成若干附加页，不能因此拆分正文节点。`include_cover` 仅控制附加封面页，不移除正文自己引用的同一张图片。

`reflowable` 预设中显式写入 `spread`、`first_single`、`page_width` 或 `page_height` 属于不适用字段错误；不承诺跨阅读器的字体、分页或精确版面一致。

`fixed` 中每个正文节点对应一个固定视口的完整 Markdown 文稿。溢出处理与 PDF `fixed` 相同；不能自动按图片拆页。`spine` 始终保持逻辑阅读顺序；方向与单双页通过目标格式的属性表达。`first_single` 在 `double` 时按第 7 节使第一个正文节点以单页宽度单独居中，`single` 时保留但不参与配对。单独添加的封面、目录不参与正文节点两两配对，必须声明为独立附加页。阅读器是否采用并排效果不改变文稿顺序。

具体映射使用所引用 EPUB 3.3 的属性：`direction` 写入 `spine` 的 `page-progression-direction`；`fixed` 写入 `rendition:layout=pre-paginated`，`single`／`double` 分别使用 `rendition:spread=none`／`rendition:spread=both`。双页正文按每个正文项写入 `page-spread-left` 或 `page-spread-right`，明确左右位置；首项单独居中与附加页使用 `rendition:page-spread-center`。每个固定正文视口均为 `page_width × page_height`，不把双页组合的总宽误用为单页宽。[EPUB 固定布局](https://www.w3.org/TR/2026/REC-epub-33-20260113/#sec-fixed-layouts)

`embed_font = true` 时必须嵌入实际使用且允许嵌入的字体，不能仅保留一个无法解析的字体名称。有可见文字的 `fixed` 输出要求此值为 `true`，并在字体就绪后检查布局；无法满足时拒绝该次出版。纯图形页面没有字体依赖时不要求添加无用字体。嵌入字体仍不等于承诺所有阅读器渲染字节或像素相同。

`embed_font`=`false` 表示不嵌入字体；如果最终样式实际选择了包内字体，这与完整应用该字体相冲突，该次出版须失败或明确选择有损替代。作者可以在预设中改用 `generic` 字体以消除该依赖。`true` 的检查覆盖正文、导航、附加页及实际使用的后备字体；未用到的字体集成员不要求嵌入。

### 11.4 预设错误、依赖与可复现性

TOML 无法解析时不能执行其中任何预设；可解析时，一个预设的错误不自动使其他预设失效。重复预设 ID 使整个预设集合的引用不明确，必须修复后再执行。无效 `default_preset` 不阻止显式选择其他合法预设。

出版预检至少检查：核心结构、所选阅读序列、实际使用的语法能力、最终有效样式、目标格式要求、全部输出资源和链接目标、字体可用性及实际布局。遇到不支持的必需语法或资源，必须失败，或由用户明确选择并标注有损转换；不能用“已保留在 MDK”代替出版物里的完整内容。

只有选中的预设及其依赖参与该次出版资格判断。无效 PDF 预设不阻止正文保存、基础内容交付或独立的合法 EPUB 预设。

本规范不承诺不同引擎生成字节相同或分页相同的 PDF。需要可复现出版时，可以使用预设级必需扩展固定引擎、字体摘要等条件；不因此把整个工程绑定到某台机器或某个应用版本。摘要不能代替字体文件或来源验证。

### 11.6 共享的封面与元数据规则

“合法封面”指 `metadata.cover` 的字面路径位于 `resources/`、目标为存在的普通文件、数据非空且能安全解码成具有正尺寸或可解析比例的静态图像。PDF／EPUB 出版器必须支持静态 PNG 和 JPEG 封面；SVG 等其他格式须声明支持，执行第 15 节的限制，未支持时报告 `unverified` 并阻止需要该封面的完整出版。动画资源不能静默取首帧作为静态封面。

附加封面页使用居中 `contain`，保留完整图像；以最终 `body.background_color` 补足留白。PDF 使用扣除页边距后的区域，EPUB `fixed` 使用单页视口；`reflowable` 按可用区域等比适配。封面不继承正文 `reading.image_fit` 的裁切规则。PDF 可以保留 SVG 矢量，也可以做保持完整视觉内容的图像转换并报告；无需强制栅格化，更不得为此栅格化整篇正文。转换不能隐藏活动内容、缺字或解码错误。

EPUB 若声明 `metadata.cover`，必须把可用封面资源纳入 manifest 并标记唯一的 `cover-image`；`include_cover` 只控制是否另加线性阅读中的封面页，因此 `false` 不取消 EPUB 的封面资源依赖。PDF 仅在 `include_cover` 或正文等实际使用该图像时依赖它。格式转换后使用实际输出资源的媒体类型和路径，不把源文件路径误写成产物引用。

已提供的作品元数据按下表写入；缺省不编造，允许空文本的字段为空时可以省略。PDF 必须为已提供的表列元数据写入对应的文档级 XMP 属性；仅在提供 `language` 时写入 `Catalog.Lang`。缺省字段不以空字符串等占位值写入产物。Info 信息字典是可选的兼容镜像，提供时须按表映射并与 XMP 一致。XMP 的语言替代文本使用 `x-default`，作者使用有序数组，语言和出版者使用集合，标识符是单个文本值；不得把作者顺序丢掉。[Adobe XMP Dublin Core 定义](https://developer.adobe.com/xmp/docs/xmp-namespaces/dc/)

| MDK `metadata` | EPUB | PDF |
| --- | --- | --- |
| `title` | `dc:title` | `Info.Title` 与 XMP `dc:title` |
| `creators` | 按数组顺序写多个 `dc:creator`，以文档顺序表达优先级 | XMP `dc:creator`；`Info.Author` 以分号加空格连接姓名，仅作兼容显示 |
| `language` | `dc:language` | `Catalog.Lang` 与 XMP `dc:language` |
| `description` | `dc:description` | `Info.Subject` 与 XMP `dc:description` |
| `publisher` | `dc:publisher` | XMP `dc:publisher` |
| `rights` | `dc:rights` | XMP `dc:rights`；不把许可文本当成 DRM 授权 |
| `identifier` | `dc:identifier`，作为 `unique-identifier` 所指的作品标识 | XMP `dc:identifier`；不是 PDF 文件 trailer 的 ID |
| `cover` | 上述封面资源／页面规则 | 上述附加页规则，不作为文件路径写入 Info |

XML 和 PDF 字符串必须正确编码／转义，不执行元数据中的标记。应用可以记录真实的生成工具与产物时间，不能把当前用户名、本机路径或账号自动当作作者或作品信息。若 PDF Info/XMP 记录生成时间，取与本次产物生成一致的时刻；实现须在出版报告中说明工具及时间等生成值。上述要求不引入新的 MDK 持久时间字段。

## 12. 持久资料、可重建状态与交付筛选

| 位置／对象 | 数据性质 | 普通保存 | 基础内容交付 |
| --- | --- | --- | --- |
| 正文、资源、核心控制文件 | 工程资料 | 保留用户未删除的内容 | 默认保留 |
| `meta/` | 批注、书签及其他持久资料 | 保留 | 默认保留 |
| `state/` | 可完全重建的应用状态 | 保留未主动更新／清理的状态 | 默认排除，可显式选择携带 |
| 其他未知安全普通文件／字段 | 性质未知，按持久资料处理 | 保留 | 默认保留 |

`state/` 的可丢弃性质由路径命名空间明确定义，不依赖读取器理解内部格式。写入器不得把作为唯一副本的正文、批注、未保存草稿、许可证或其他不可重建内容放进去。状态建议以 `state/<反向域名>/` 隔离，各应用只能主动更新自己认识的数据。

未知状态格式不授权执行代码或加载插件。普通保存不顺便清理整个 state；独立的“清理可重建状态”操作可以清理它。未保存修改的恢复副本应放在独立恢复区，不能当作缓存自动丢弃。

本规范不定义 `include_meta` 这样的整体丢弃开关。用户可以在某次交付中选择去除批注等持久资料，但必须明确展示删除范围；这一选择属于本次操作，不因工程里某个布尔值而自动获准。完成筛选后重新检查剩余已知引用。

任何筛选都作用于交付副本，不改变源工程。可重建状态被排除时，核心与已知扩展不得留下指向 state 的内容依赖。未知持久数据不因“没有发现引用”而被排除。

## 13. 扩展能力与未知数据

### 13.1 名称与版本

能力 token 使用 `<反向域名>@<正整数主版本>`，例如 `org.example.review@1`。反向域名部分至少含两个点分标签；每个标签由小写 ASCII 字母、数字和内部连字符构成，以字母开头、以字母或数字结尾；版本不含前导零。`mdk` 顶级前缀保留给另行发布的 MDK 标准能力，本文不注册任何额外语法 token。

本规范的设置目录注册非语法能力 `mdk.settings-full@1`，定义完整 `settings` 字段及对应的 `publication` 样式覆盖。它直接扩展本文引用的标准设置目录，不启用新的 Markdown 语法；完整、部分与基础支持的边界以设置目录为准。

`mdk.toml` 的 `[features]` 允许两个字符串数组：

| 字段 | 缺省 | 含义 |
| --- | --- | --- |
| `required` | `[]` | 理解工程意图或安全编辑所必需的扩展。 |
| `optional` | `[]` | 可缺失其增强效果，但仍可按基础内容模型使用的扩展。 |

两个数组中不得重复 token，也不得为同一能力同时声明不同主版本。数组顺序不表示解析优先级。多个语法扩展有冲突时，扩展规范必须给出确定的组合规则；没有可用组合规则的实现应报告冲突，而不是按插件加载顺序猜测。

扩展数据位于四个核心 TOML 根级的 `extensions` 命名空间表、已定义的对象级 `extensions`，或 `meta/` 中的扩展目录。工程根级及正文／节点对象的扩展版本只能来自 `mdk.toml` 的工程级 `features`；预设自己的 `extensions` 可以使用该预设 `requires` 或一致的工程级声明。预设 `requires` 不为其他对象或整个工程提供版本。

没有版本声明的数据按不透明值保留，不推断它是“最新版”，不承诺语义解释或版本迁移。扩展键中不另加会与能力声明冲突的核心 version 字段；扩展自身内部版本由其规范定义。

出版预设的 `requires` 只影响该预设。若同一能力也在工程级声明，版本必须一致。只用于锁定 PDF 渲染器的能力不应提升为整个工程的必需能力。

每个 `requires` 数组同样禁止重复 token 和同一能力的多个主版本；不同预设可以分别要求不同主版本，只要不与工程级声明冲突。能力是否支持应按当前操作及实现声明的角色判断；读取器只识别或验证字段，不等于预览器或出版器已经能执行它。标准设置字段的含义不因漏写 optional 声明而改变，已知实现仍须按字段规则解释并报告漏声明；未知实现不得猜测已支持。

### 13.2 支持与降级

| 情况 | 允许的处理 |
| --- | --- |
| 全部 required 已支持 | 正常解释核心及相应扩展，按操作执行校验。 |
| 有未知 required | 可以只读查看源码和附件、恢复或原样复制；不得正常编辑覆盖，也不得把扩展校验记为通过。 |
| 有未知 optional | 可以基础阅读与可安全执行的编辑；保存其数据，报告缺少的增强能力。 |
| 选中预设的 `requires` 不支持 | 禁止执行该预设；其他预设与基础编辑不因此失效。 |
| 安全普通文件或未知字段 | 保留，不自动执行、不解释为脚本，也不删除。 |

optional 不表示“允许任意破坏其数据”。当重命名、删除或结构编辑可能破坏未知扩展的关联时，应限制该操作，或在用户确认后输出明确说明损失的独立副本。不得通过删除 required 声明来掩盖实际仍存在的必需语义。

任何扩展都必须遵守容器安全、路径边界、正文权威性、状态隔离和未知数据保留规则；扩展不构成豁免。新增核心字段含义或不兼容目录语义应修订核心版本，不能藏在扩展中改变已定义字段。

### 13.3 扩展声明示例

### 13.4 无损保留

文件中未修改条目解压后的字节必须保持一致；不要求 ZIP 压缩结果、时间戳或整个 MDK 文件字节不变。修改 TOML 的已知字段时必须保留未知字段及值；注释和键顺序应尽量保留，但不属于字节级保留保证。

正文扩展按正文 ID，节点扩展按节点 ID，预设扩展按预设 ID 关联，不能按数组下标迁移。删除对象属于显式删除该对象及其附属字段；对其他对象的引用仍须检查。

四个核心 TOML 的根级扩展关联当前工程及其所属控制文件，不因更改数组顺序而迁移到某个正文或预设；字体集扩展若由独立规范定义，必须按字体集 ID 关联。整体复制保留全部根级扩展；派生工程改变 `project_id` 时，对不明内部身份引用按未知扩展规则处理，不猜测改写。

无法做到上述保留的实现不能直接覆盖原工程。只读浏览、原样复制和用户明确选择的简化副本仍可提供。

## 14. 打开、保存、交付与出版

### 14.1 基础内容交付的定义

基础内容交付生成可独立携带基础 Markdown 内容的 MDK 副本。检查范围为：

1. 全部容器记录和实际保存条目的完整性，核心工程描述、正文登记和目录结构。
2. `markdown/` 下全部 Markdown，包括未编排、未登记草稿中的已知活动引用；不能用“不在目录里”掩盖未携带的基础内容依赖。
3. 作品封面，以及设置的字体字段、后备列表和字体集成员中可解析且路径语法合法的全部显式字体路径，还有已支持工程扩展明确声明的内容依赖。基础交付须携带这些已声明字体文件；具体出版只检查最终输出选择的字体与后备链，不被未用字形阻断。其他设置字段非法不隐藏已经明确解析出的字体路径。
4. 工程级 required 能力及其基础交付要求；未支持 required 时不能宣称基础交付通过。

基础交付的目标是交付可继续编辑的自包含工程，不只是当前画面：未选中的已登记字体以后仍可被启用，所以已知登记路径缺失仍阻断完整基础交付。用户可显式修复或删除不用的登记后重新校验；普通保存仍可保留未完成工程，出版仍按实际依赖单独判定。

在以上范围内，缺失文件、缺失 Markdown 锚点、不安全活动引用和外部展示依赖均阻止完整基础交付。HTTP(S)/mailto 导航链接不要求打包其远端内容；网络是否可达不参与包内存在性判定。

内容校验还须区分“依赖存在”和“可按用途呈现”：在检查范围内不支持的图片格式、字体格式或媒体片段使对应呈现结果为 `unverified`，不能记为通过；仅供下载／提取的普通附件无需因此要求预览解码器。

独立的出版预设、无效展示字段、未知 optional 增强内容及不透明附件不自动进入基础可渲染性保证。它们仍须保留，并在报告中明确列为未验证或有错误；“基础内容交付通过”不能表述为“全部预设、附件和扩展都可用”。语法损坏的可选设置不能据此隐藏已被其他已知数据引用的资源。

### 14.2 操作矩阵

| 情况 | 打开 | 普通保存 | 基础内容交付 | 指定目标出版 |
| --- | --- | --- | --- | --- |
| 起始签名不符合本规范 | 容器 `unverified`，未识别问题为 `error`；可安全查看原始数据 | 该 `error` 禁止按 v2 覆盖 | 不能宣称通过 | 禁止 |
| ZIP 损坏、危险路径、重复项、错误 mimetype／物理顺序 | 只允许安全恢复 | 禁止覆盖 | 禁止 | 禁止 |
| `mdk.toml`／`contents.toml` 缺失、非法 TOML、版本或核心字段错误、目录环／悬空 ID | 只读恢复 | 修复前禁止覆盖 | 禁止 | 禁止 |
| 登记正文路径合法但文件缺失 | 显示缺失项 | 允许保存并报告 | 禁止 | 被选阅读序列需要时禁止 |
| 已知资源缺失、不安全链接 | 保留源码，禁止危险访问 | 允许保存未完成内容 | 检查范围内禁止 | 该次输出依赖时禁止 |
| 外部展示资源 | 默认不加载 | 允许保存 | 基础内容依赖时禁止 | 必须按目标规则显式处理 |
| 未编排正文、未引用附件 | 保留 | 保留 | 保留并按范围检查 | 不自动成为出版正文 |
| `settings.toml` 语法／字段错误 | 报告并临时回退 | 可保留原文件；可解析时允许按第 10.3 节局部修复 | 可交付基础内容，展示记为失败／未验证 | 最终有效依赖仍错误时禁止 |
| `publication.toml` 或其中某预设错误 | 不影响基础读取 | 可保留原文件；可解析时允许按本节局部修复 | 可交付基础内容，出版配置单独报告 | 仅所选预设及其依赖决定资格 |
| 未知 required | 只读基础恢复 | 禁止正常覆盖 | 不能宣称通过 | 禁止 |
| 未知 optional、未知持久数据 | 基础打开并报告 | 保留，必要时限制有风险的编辑 | 保留并说明未验证范围 | 完整输出无法保证时拒绝或显式有损转换 |
| 超出实现资源限额 | 停止相关操作，报告限额 | 不保存成截断工程 | 不宣称通过 | 不发布不完整输出 |

出版可以不使用某些未编排草稿，因此草稿中的内容缺失不影响不依赖这些草稿的出版。核心结构错误和容器安全错误仍然阻止所有正常出版。这个区别不能用于删除或遗漏保存源工程里的草稿。

新提交的 `mdk.toml`／`contents.toml` 必须合法；不能把非法目录数据作为正常工程保存。可选 `settings.toml`／`publication.toml` 的已有错误可随未修改内容保留；可解析文件的局部编辑遵守第 10.3 节的“修改项及关联约束合法、未触及错误保留”规则，`publication.toml` 包括受影响预设及 ID／引用约束。整份重新生成或替换时须通过对应已知结构和字段校验。非法编辑缓冲区可以进入独立恢复记录，不得因此把正常工程标为完整保存。

### 14.3 打开顺序

1. 识别 ZIP 本地头和前两项，按大小限额读取 mimetype 与 `mdk.toml`。
2. 校验中央目录、记录边界、路径、类型、重复项、声明容量与支持范围；读取内容时继续校验实际输出。
3. 验证 `format_version`、工程字段和能力声明；决定完整打开、受限读取或恢复。
4. 解析 `contents`，建立正文表和无环目录，按规则计算阅读序列。
5. 解释可选 `settings`；`publication` 按需解释，错误单独报告。
6. 读取需要展示或校验的内容，应用统一 Markdown 规则和已支持扩展；图片、字体等按隔离策略解码。

可以按需解压资源以节省开销，但不能把尚未检查 CRC 的全部附件标为已验证。完整交付和覆盖保存必须验证实际保留的条目，不能将已知损坏的附件原样重新封装后称为成功完整保存。

### 14.4 保存与安全发布

1. 获取一致快照：正文、路径、目录、设置和资源须对应同一确认状态，不得混用旧目录和新正文。
2. 普通保存保留所有未被显式删除的持久数据；交付筛选只作用于副本。应用缺省值不因打开文件自动写回。
3. 构造标准 ZIP，保证前两项及其他容器约束，不添加任何模式前缀。
4. 在目标所在文件系统创建唯一临时文件，写完并刷新数据后重新读取，检查容器、实际条目校验值及本次操作所要求的结构／内容。
5. 校验成功后，通过平台支持的原子发布／替换完成提交。无覆盖授权时使用不覆盖已有文件的发布方式；不得用“先删旧文件再重命名”代替。
6. 失败时保留原工程和未保存修改；只有发布成功才更新对应已保存状态。无法提供所需保证的平台必须报告限制。

必须防止源工程被外部修改后遭到静默覆盖。仅在保存前检查一次时间戳不足以消除检查与替换之间的竞争；实现须使用适合其平台的并发协议、锁及提交时检查，明确不受协调的外部写入限制。文件名和 `project_id` 均不是修订号。可以用整个已读取文件的摘要辅助检测，但摘要检测本身不是互斥锁。

## 15. 安全与隐私

容器读取必须防御解压资源耗尽、整数溢出、路径越界、重复名称和媒体解码问题。控制文件、未知附件和目录深度同样受资源限额约束。

HTML、SVG、字体及其他媒体必须在受限制的环境中解析／渲染，阻止脚本、事件处理器、外部实体、未经授权的网络请求及宿主文件访问，并执行资源限额。可以采用沙箱进程、受限解码器等满足这些要求的机制，不以单一进程架构作为符合性条件。SVG 中的活动能力必须禁用；做不到安全展示时保留原文件、显示占位信息并报告未验证。关闭外部网络加载不影响普通外部导航链接的存储。

包内的扩展、工具名称、模板或配置不得授权运行程序、安装插件、执行 shell 命令或访问宿主任意路径。核心格式不保存导出目录或覆盖授权。

默认交付不携带 `state/`。`meta/` 和未知持久附件可能包含作者信息、批注或其他资料，必须按第 12 节的规定，允许用户查看并选择交付范围。普通保存不得静默删除这些数据；出版不得自动加入本次输出已声明或经用户确认的范围之外的这些数据。用户显式选择的删除、筛选或出版内容仍按第 11、12 节处理。

SHA-256 等内容摘要若由扩展提供，只能证明与给定摘要的一致性；来源认证需要独立定义签名范围、密钥信任和修改后处理。本规范不定义签名或加密方案。

## 17. 一致性检查用例

实现应提供正例和反例，不以“自己写出的文件能自己打开”作为完整符合性的证据。

| 用例 | 预期 |
| --- | --- |
| 最小工程 | 标准 ZIP 工具能直接读取；工程读取器得到空目录与 `default` 模式。 |
| ZIP 前放置任意前缀 | 容器 `unverified`，`mdk.container.unrecognized` 为 `error`；禁止按 v2 覆盖，不断言原格式已损坏，不自动剥离前缀。 |
| 首项正确但 `mdk.toml` 不是物理第二项 | 容器不符合；中央目录顺序不能修正此问题。 |
| `format_version` 为字符串或 2.0 | 核心错误，即使宿主解析后数值等于 2。 |
| 同一路径登记两个正文 ID | 核心错误；应使用多个节点引用同一正文。 |
| 两节点引用同一正文 ID | 合法，两次展示，共享文件内容。 |
| 正文节点有子节点，或有空分组节点 | 合法；按父节点在前遍历。 |
| 目录环、父 ID 缺失、同级 `order` 重复 | 核心错误；禁止猜测或截断后覆盖。 |
| 深度超过实现声明的限额 | 报告实现限制；格式本身不设固定深度上限。 |
| 移动父节点 | 后代 parent 和正文 ID 不必改写；阅读顺序正确更新。 |
| 正文登记存在但文件缺失 | 未完成工程可保存，基础交付失败。 |
| 多图文稿、纯文字 `comic`、RTL 奇数末项 | 保留完整 Markdown；按正文节点进行配对和定位。 |
| 合法 `book`/`comic` 改为 `default` | 核心结构仍合法；元数据和显式设置不变时，核心出版语义不变，阅读视图的模式缺省值可以变化。 |
| 中文／同名／生成锚点与既有锚点或去重后缀冲突的标题 | 按同一算法生成锚点，既有目标不重复。 |
| 指向重复展示文稿的链接 | 同文稿留在当前节点；其他文稿选首次出现。 |
| `../resources/a%23b.png` | 正确解析字面文件名；查询／片段不混入文件名。 |
| `%2e%2e` 越根、编码分隔符、二次解码陷阱 | 禁止危险访问；不会逃出工程根。 |
| 草稿缺失引用但未进入出版序列 | 基础交付失败；不依赖草稿的出版可独立判断。 |
| 未使用 PDF 预设非法、EPUB 预设合法 | 保存与基础交付不被 PDF 阻断，EPUB 按自身依赖判断。 |
| 固定页面溢出 | 出版失败，不隐藏内容或自动栅格化。 |
| 未知 required 与未知 optional | 前者受限只读；后者保留并报告增强能力未验证。 |
| 未知出版 `requires` | 仅阻止对应预设。 |
| 完整设置能力为 optional，但读取器只支持基础字段 | 保留全部设置、报告未支持的增强项；不宣称完整应用。 |
| 出版覆盖 `body`，标题未显式指定对应字体或颜色 | 按覆盖后的 `body` 重新解析继承；不复用预览缓存值。 |
| 预览几何矛盾、目录标题等级范围颠倒 | 报告并按设置目录临时回退关联字段组，不自动修复源文件。 |
| `settings` 整份语法损坏，但预设覆盖字号 | 普通保存可保留原字节；不能仅凭字号覆盖正常出版。 |
| 字体集只使用 regular，未使用的 bold 文件缺失 | 基础交付失败；不选择该 bold 的出版按自身依赖判断。 |
| 停用预设或关闭样式后重命名字体 | 仍更新已知路径引用；开关不豁免引用维护。 |
| EPUB 不把目录放进 spine | 必需导航仍存在，且不改变正文顺序。 |
| `nodes` 包含只含分组节点的空分支 | 源工程保留；出版派生导航剪去该分支，不生成无目标叶分组。 |
| EPUB 不嵌入字体但最终使用包内字体 | 报告出版配置冲突，不静默替换为本机字体。 |
| 小文件合法使用 ZIP64、descriptor 无签名 | 前两项以外按 ZIP 结构读取；不扫描数据猜测 descriptor。 |
| 非法媒体片段或不支持的展示格式 | 源码仍保留；存在文件不等于可完整呈现，报告失败／未验证。 |
| state 中未知格式，meta 中未知格式 | 交付可按默认排除前者，保留后者；内容不能依赖 state。 |
| 保存中断、磁盘写入失败或外部修改 | 不覆盖成半个工程，不清除未保存状态。 |
| ZIP64、大资源或过深目录 | 区分合法格式、未实现能力与资源限额。 |
| 未编辑 Markdown、未知附件和扩展 | 解压后字节不变，扩展不因数组重排附着到其他对象。 |
| 无效 toc 范围下仅修改独立字号 | 允许局部修复，保留并报告原有 toc 错误；修改 toc 本身则须修复关联范围。 |
| 同一 PDF 预设省略 `include_toc`/`chapter_break`，随后切换 `mode` | 始终解释为 `false`/`none`，不随 `mode` 改变。 |
| 引用块／列表中的标题、标题内删除线、HTML 块中的伪标题 | 前两者参与统一锚点提取；HTML 块不产生标题锚点。 |
| `contents` 仅含根级 `extensions` 或未知字段 | 核心目录为空，但必须保留这些数据，不能替换成空文件。 |
| 空正文节点与仅有分组节点 | 前者可出版，后者不具备出版正文。 |
| 字面反斜线、C1 控制字符或指向目录的 URL | 拒绝对应路径／引用，不能交给浏览器归一化后猜测。 |
| Windows 保留名或尾部点在不支持的宿主解包 | 报可移植性限制，不静默覆盖、截断或重命名。 |
| 相邻 `order` 无整数空位 | 同级保序重排，一次保存；ID、对象扩展及后代相对关系不变。 |
| EPUB `metadata.cover` 存在而 `include_cover`=`false` | 不生成附加封面页，但仍验证并打包 `cover-image` 资源。 |
| EPUB 缺少作品标识，或 PDF 文字字体不能嵌入 | 阻止完整出版；不静默编造标识或替换字体。 |
| 双页 4 个正文节点，`first_single = true` | 第一项以单页宽度居中；第二、三项配对；第四项在下一组首项位置，LTR 左／RTL 右。 |
| PDF 的 `include_cover`／`include_toc` 四种组合 | 仅生成开启的附加页，封面在目录之前，正文最后；都关闭时直接从正文开始。 |
| PDF 未提供作品语言或其他可选元数据 | 不编造 `Catalog.Lang` 或对应 XMP／Info 占位值；不因此阻止其他条件已满足的 PDF 出版。 |
| `metadata.identifier` 为相对路径、盘符路径、非法转义或带片段 URI | 核心 `fail`，`mdk.core.invalid`／`error` 定位该字段；修复前不正常保存、交付或出版。省略字段本身不构成核心错误。 |
| 第三方目标存在，但 `default_preset` 引用其配置 ID | 核心默认预设引用错误；扩展自己的选择机制不使该引用合法，不自动执行。 |
| 未知持久附件包含批注信息 | 普通保存保留；没有被声明或确认纳入输出时不得自动加入出版物。 |

## 18. 本规范的取舍与后续扩展

本规范已经明确：标准 ZIP、包内 `mode`、唯一核心版本、正文与目录身份分离、具名分组、独立显示名、共同 Markdown 规则、确定的标题锚点、作品元数据、展示／出版分离、持久性分类及能力声明。

以下项目可以作为后续独立、版本化的扩展规范，不能仅以本文列出了名字就声称已有标准支持：

- 脚注、数学、提示容器：需分别定义完整语法、冲突处理、引用提取、源码往返和出版降级；不直接把某个解析器插件的当前行为当规范。
- 批注与书签：应绑定正文身份，记录原文摘录、上下文及修订信息；可参考 [W3C Web Annotation 的文本选择器](https://www.w3.org/TR/annotation-model/#text-quote-selector)。无法可靠重定位时保留为失效标注，不猜测挂接。本文不定义其 JSON 字段。
- 资源索引与摘要：可辅助去重、来源记录和变更检测；不能让摘要取代正文相对路径或来源认证。
- 稳定的显式段落／标题锚点、特定目录出现位置链接：需与普通 Markdown 和正文 ID 模型一起设计。
- 多个阅读集合、选章出版、拼版、页眉页脚、媒体覆盖和可复现渲染：通过具体目标配置或扩展表达，不挤入最小核心。

完整版本历史、实时协作、云账号、插件执行、DRM 和自定义脚本不属于本规范核心。应用可以提供相关功能，但不能要求基础读取器实现这些系统才能提取和编辑基础 Markdown 内容。
