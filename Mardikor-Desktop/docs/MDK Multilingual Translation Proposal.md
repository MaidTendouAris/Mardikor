# MDK 多语言与逐行翻译提案

2026-11-19 · 开发草案 1 · 适用于 MDK v2 的通用、书籍和漫画工程。

作者在已有文稿上选择「新建翻译」，选定目标语言，即可得到同目录的 Markdown 译稿。例如，选择英语（美国）会从 `markdown/游记.md` 生成 `markdown/游记.en-US.md`。译者可以逐行对照、分次保存。原作者继续改稿后，译者能直接找到新增和需要复核的行。

首版交付是**创建译稿、人工翻译和跟踪原文变更**。自动生成自然语言译文、整书按语言切换和按语言出版可分别立项。下文的字段、界面和验收项均为拟议设计。核心规则沿用 [MDK v2 主规范](<MDK Format Specification v2.md>)。

## 1. 从已有文稿创建译稿

1. 在文稿目录的正文节点、整体目录的 Markdown 文件或当前文稿菜单中选择「新建翻译」。同一正文在多个节点出现时，共用同一组译稿。从已有译稿选择「添加其他语言」时，界面显示组内原文的名称，并以这份原文为底稿。
2. 选择器显示可搜索的语言名称和完整标签，如「简体中文（zh-Hans）」「繁體中文（zh-Hant）」「English (en-US)」，也接受符合工程语言字段规则的自定义标签。首次建组时可指定原文语言，以作品的 `metadata.language` 作可修改的建议值；未知时允许留空。创建译稿只需选定目标语言。原文语言和目标语言的选择都属于这组文稿，应用界面语言独立。
3. 确认前展示包内目标路径。取原文当前文件名，仅去掉最后一个小写 `.md`，追加 `.<目标语言>.md`。例如 `篇章/海.上篇.md` 的繁中译稿为 `篇章/海.上篇.zh-Hant.md`。即使原文名本来以 `.en` 结尾，也保留该部分。使用正文 ID 查找同一组，组内每个目标标签限一份；大小写等价，再次选择已有语言时打开现有译稿。已知原文语言与目标相同时提示另选语言。标签含义和大小写比较沿用 [RFC 5646 §2.1.1](https://www.rfc-editor.org/rfc/rfc5646.html#section-2.1.1)。
4. 若候选路径已被其他正文、未登记文件或目录占用，依次建议 `游记-2.en-US.md`、`游记-3.en-US.md`。同时检查包内字面路径和大小写、Unicode 规范化后的可移植冲突，按核心路径规则处理新名称。建组只关联本次新建的文件。重试创建同一译稿仍按正文 ID 和标签找到已有结果。
5. 以窗口中当前原文快照为准，包括未保存的修改。逐行复制其 Markdown 源码作为译稿起点，保留标题、表格、围栏、链接、缩进、行尾空格、换行和 BOM。直接复制也保留图片的相对路径。新文件取得独立正文 ID 并登记到 `contents.toml`；原文若为 `markdown/` 下的未登记草稿，在同一操作中登记。创建译稿默认不增加阅读节点。
6. 创建后进入对照编辑，左侧定位原文，右侧编辑译稿，显示语言、当前行状态和下一个待处理行。创建是一次工程编辑，由现有手动保存、自动保存及草稿恢复提交。独立 `.md` 可通过已有「Markdown 转 MDK」进入此流程。

## 2. 一行怎样翻译

**行指 Markdown 源码的物理行。** 预览换行、窗口宽度和分页均不参与计数。解析 UTF-8 后忽略文件开头的单个 BOM，以 CRLF、LF 或 CR 分行。空文件有零行，`a\n` 有一行，`a\n\n` 有两行，`\n` 有一行空行。行内空格、制表符和其他字符都参与比较。编辑与保存仍遵守核心规范的原始字节保留规则。

每个原文行取得永久行 ID。各语言分别把它对应到译稿中一个连续的行段。一行原文可以译成多行，一行译文也可以留空。译者可以在对照视图中插入换行，新增的译文行归入当前行段。多句合译时，可将译文写在第一行对应的位置，对后续原文行逐一选择「确认省译」；这些行可以贡献零个物理译文行。省译须显式确认。原文 ID 和对齐信息保存在工程元数据中，Markdown 正文可直接供其他编辑器读取。

| 译者看到的状态 | 如何产生 | 如何处理 |
| --- | --- | --- |
| 待译 | 新稿中复制的正文行，或原文后加、尚无对应行段的行 | 写译文，或明确选择「沿用原文」。 |
| 草稿 | 已编辑译文，尚未确认 | 可随时保存并继续；选择「确认译文」才计入完成。 |
| 已确认 | 用户已确认译文、沿用原文或确认省译 | 保留这次确认依据的原文摘要。初建时，空行及仅含 ASCII 空格、制表符的行自动记作沿用。 |
| 原文已改，待复核 | 当前原文与译者上次据以工作的版本不同 | 显示当前原文和现有译文；译者修改或接受现状后重新确认。 |
| 需整理对应关系 | 原文行已删除、译稿存在未关联的行，或外部编辑使映射过期 | 保留译稿文字，允许重连、保留为独立译文行或由用户删除。 |

对照界面支持按状态筛选和批量「沿用原文」。例如，译者可整段沿用代码，另译代码块前的说明。标题、列表、引用、表格和图片说明仍按源码逐行编辑，预览按完整译稿解析。进度以**当前原文行数**为分母，仅统计与当前原文相符的三种确认结果；另列待整理项。空原文显示「暂无原文行」。普通保存允许任意进度。

「确认译文」保留当前译文；「沿用原文」将对应行段替换为当前原文行；「确认省译」将该行段的物理行数设为零。后两项会覆盖已有译文时，先显示实际受影响的文字，整次操作可撤销。手动删除某行段的全部物理行会撤销该对应并使原文回到待译，译者仍可单独确认省译。保留一个实际空白行时，编码须使该行能按上述分行规则读回。

## 3. 原文改稿和重新对齐

例如，原文依次是「出发。」「过桥。」，英语译稿已确认 “We set out.” 和 “We crossed the bridge.”。作者在两句之间加上「下雨了。」后，对照视图在中间增加一行待译，前后两句继续关联原 ID。直到译者在中间填写或接受底稿，英文文件仍只有原来的两句。若作者接着将「过桥。」改成「过木桥。」，仅第二份已有译文需要复核。日语译稿有自己的确认结果，各语言分别计算进度。

| 操作 | 原文身份及译稿的处理 |
| --- | --- |
| 修改单行内容 | 编辑器能追踪该行时沿用行 ID。保留各语言的译文与旧基准，展示待复核提示。仅转换换行形式或文件开头 BOM 时，行摘要相同。 |
| 插入、复制原文行 | 每个新增行取得新 ID；即使文本相同也独立待译。各语言显示空位，译者首次填入时按相邻已对齐行定位。若相邻行在译稿中顺序冲突，先让译者选择插入位置。 |
| 移动或删除原文行 | 明确的移动保留 ID，界面按原文新顺序对照，标出译稿顺序差异，译者可选择同步行段顺序。删除有译文的原文行时，旧译文留在译稿原位置，进入待整理列表。 |
| 拆分、合并原文行 | 将受影响的旧行退役，为结果行分配新 ID。对照视图列出旧译文供重新分配；人工重新关联后进入草稿。可追踪的撤销／重做一起恢复正文、对应关系和确认状态。 |
| 单独编辑译稿 | 对照编辑能定位到的修改只将所改行段转为草稿。通过其他源码、可视化、CLI 或解包编辑途径修改时，重开或切回对照视图前按第 4 节检查。 |
| 改名、复制或移除整篇文稿 | 改名或移动保留正文 ID，按核心规则维护相对链接；原文改名只影响**以后**新建译稿的建议名。普通「复制文稿」复制出独立正文。显式解除译稿关联保留其 Markdown；移除组内原文前展示受影响语言，允许解除整组关联并保留各译稿。仅移除目录节点照常保留正文和翻译关系。 |

## 4. 包内表示与保存

拟使用版本化能力 `mdk.translation@1`。创建第一份译稿时，在工程的 `features.optional` 追加此 token，并创建固定路径 `meta/mdk.translation/index.json`。其他能力声明和扩展数据按原样保留。普通 v2 阅读器仍可按核心目录阅读作品。无法解释扩展的写入器按主规范 §13 处理未知持久数据及可能破坏关联的操作。

以下是一个完整的翻译索引示例。两篇已登记正文 `doc-travel`、`doc-travel-en` 各含一行，原文是「雨停了。」（不含引号），译文是 `The rain stopped.`，译者已确认。换行符不计入摘要。

```json
{
  "groups": [{
    "source": "doc-travel",
    "language": "zh-CN",
    "lines": [
      {"id": "l-rain", "hash": "fa2f6df06f1f610b5fad5d9f92eb10c822c9ad28183d8ff82a13eb06b0ae9440"}
    ],
    "targets": [{
      "document": "doc-travel-en",
      "language": "en-US",
      "spans": [{
        "line": "l-rain",
        "base": "fa2f6df06f1f610b5fad5d9f92eb10c822c9ad28183d8ff82a13eb06b0ae9440",
        "hashes": ["3675bf13de90577c1d8c718a11a00253707965c70facd64cdd8cc80dbfc35b54"],
        "state": "confirmed"
      }]
    }]
  }]
}
```

| 字段 | 读写约定 |
| --- | --- |
| `groups[]` | 每组有一个 `source` 和一份或多份 `targets`。二者引用已登记正文 ID。一个正文在整个索引中最多承担一个角色，排除自引用、链式翻译和环。删除最后一份关联时可移除空组。 |
| 组的 `language`、目标的 `language` | 分别表示原文和该译稿的语言。前者可省略，后者必需。组内按完整标签做 ASCII 大小写无关比较；不按主语言合并地区或文字变体。 |
| `lines[]`、可选 `retired[]` | 前者按原文物理顺序列出每行的 `id` 和 `hash`。行 ID 沿用 v2 §4.2 的字符规则，在组内唯一。后者列出仍被译稿引用的已删除行 ID 字符串，与活动 ID 互斥。新行使用新 ID。 |
| `spans[]` | 每种译稿按**译稿文件自身顺序**列出行段。`hashes` 是该行段逐物理行的摘要数组。按序拼接所有数组，必须逐项匹配整份译稿。每种语言对同一原文 ID 最多有一个行段。尚无译文的新增原文可无行段。 |
| `line`、`base` | 已关联行段必须同时提供原文行 ID 和建立对应或最近确认时的原文摘要。`line` 必须在 `lines` 或 `retired` 中。手工新增的独立译文行段省略两字段，作为待整理项，可显式保留为译者补充（见下行）。 |
| `state` | 已关联行段取 `pending`、`draft`、`confirmed`、`verbatim` 或 `omitted`。初建复制行按第 2 节记为 `pending` 或 `verbatim`。沿用要求恰有一个摘要且等于 `base`；省译要求 `hashes = []`；其余已关联状态至少含一行。未关联行段仅可用 `draft` 或 `addition`，均至少含一行；`addition` 表示用户已认可的译者补充。 |

**判定顺序。** 先验证 ID、语言、字段约束与两份 Markdown 的行摘要序列。摘要使用去除行分隔符后原样文本的 UTF-8 字节，取 SHA-256 小写十六进制；不裁空格或做 Unicode 归一化。映射有效时，退役 ID 优先显示「原文行已删除」；活动行的 `base` 与当前原文摘要不同时显示变更提示，已有译文进入待复核，仍为待译的行保留待译标志。重新确认时将 `base` 更新到当前摘要。修改已确认译文会撤销该行段的确认；保留为补充的行和退役行均不计入进度。

**外部编辑与恢复。** 实际行序列和记录不一致时，标记受影响的原文组或单份译稿为「需要重新对齐」，暂停依赖旧映射的写入及进度统计。原文失配影响全组，单份译稿失配只影响该语言。恢复界面并列当前 Markdown 和旧对应信息，可用唯一、顺序一致的未改行作定位建议。重复行、有歧义的移动或成段改写交给译者指认，也可暂留未关联。接受修复时重建受影响的行／行段，新关联记草稿；只保留能确证身份、原文与译文均未变化的确认。无需修复即可查看 Markdown 或保存其他合法改动，此时保留旧索引供后续恢复。索引损坏、超限或版本未知时同样保留原始数据，报告对应范围。

**事务。** 创建、确认、重新关联和解除关系时，所涉及的正文、正文登记、能力声明及索引属于同一次工程修订。自动保存、崩溃恢复、多窗口版本冲突和访问保护沿用工程保存机制。写入中断时只能恢复到完整的旧快照或新快照；版本冲突时保留待保存编辑。完整 MDK 交付默认携带索引及译稿，清理 `state/` 后仍可继续翻译；MDKE 封装照常还原同一工程字节。

## 5. 阅读、链接与出版

原文和译稿可各自预览。文稿目录在原文项上提供语言选择，切换只打开对应文稿；原文有多个目录节点时，各入口共用译稿。核心阅读顺序仍由 `contents.toml` 的节点决定，作者显式编排译稿后才进入该顺序。这样创建一份未完成的英语译稿不会让现有书籍多出一章。

正文中的相对链接照常指向其字面目标，媒体共用原资源。译者改标题后，本篇的 `#h-…` 锚点按译文标题重新计算；预检指出失效片段，译者可选择目标译稿和标题修正。创建译稿不会将所有跨文稿链接自动切换语言。普通保存、完整 MDK 交付、PDF／EPUB 出版分别使用 v2 §14 的校验范围。译稿进度单列；出版使用实际编排的正文和既有作品元数据。

## 6. 开发验收

| 场景 | 可观察结果 |
| --- | --- |
| 从两个目录节点对同一原文创建 `en-US`、`EN-us`，再创建 `en-GB` | 前两次打开同一译稿，后者独立；原目录结构和顺序一致。 |
| 原文有未保存编辑，建议路径碰巧已有未登记文件 | 对话框展示避让后的名称；新译稿包含最新编辑，既有文件字节保持原样。重复操作和多窗口过期保存均不生成半个翻译组。 |
| 空文件、BOM、混合换行、连续空行、行尾双空格、同文重复行 | 重开后行数、摘要和各重复行 ID 可复核；纯换行转换后既有确认仍有效。仅改行尾双空格会提示复核。 |
| 原文中间插入一句、移动两行、修改一句、再删去有译文的一句 | 原 ID 继续关联正确译文；新增、顺序差异、待复核和退役译文均可定位，其他语言的文字保留。 |
| 一行译成两行，另一行选择省译，代码块选择沿用 | 重开后行段边界和三个确认结果可还原；预览直接解析译稿，正文中没有对齐标记。 |
| 外部工具重排重复行并修改上下文，使快照不符 | 提示人工对齐，任意相同文本或相同行号不足以恢复确认；修复前普通保存保留外部文字与旧索引。 |
| 创建、保存、撤销或恢复时中断，或两个窗口编辑同一文件 | 重开后原文、译稿、索引、正文登记取自同一已提交版本；冲突窗口可恢复自己的待保存内容。 |
| 改名原文、从目录移除节点、解除译稿关联 | 前两种保留正文 ID 关系；解除后译稿可作为独立 Markdown 打开。 |
| 全 STORE 工程、受保护工程与 MDKE 往返；不理解可选能力的读取器打开工程 | 支持端可继续逐行翻译；基础读取器可读核心正文并按 §13 保留未知数据；未编排译稿不会混入原书 PDF／EPUB。 |
