# MDK v2 检查报告处理结果

日期：2026-11-16；目标修订：Draft 4。

本文保留 Draft 4 阶段的处理结论与验证记录；随后进行的最后一轮修正及当前定稿状态见 [MDK v2 定稿说明](<MDK v2 Finalization.md>)。

依据 [原检查报告](<test-report/MDK v2 规范检查报告.md>) 核对并修改 [v2 主规范](<MDK Format Specification v2.md>)、[设置目录](<MDK v2 Settings Reference.md>) 和 [完整设置模板](examples/v2/settings.full.toml)。原报告保持不变；其行号对应修改前版本，以下按问题 ID 和章节定位。

本次修订不引入 v1 兼容或迁移，不恢复二字节前缀。`book`、`comic` 继续共用 `default` 的 Markdown 内容模型；本草案目前只为它们定义缺省设置，不凭用途名称添加一图一页或禁止文字等限制。这是规范和示例修订，不是应用已实现 v2 的声明。

## 1. 主要设计取舍

| 报告条目 | 处理结果 | 规范位置 |
| --- | --- | --- |
| P0-1、X-1：相同扩展名／MIME 与识别 | 保留 `.mdk` 和包内 MIME 常量；通过 ZIP 结构和 `format_version` 判定 v2。新增“未识别为 v2”诊断，与已确认损坏分开。不增加旧格式识别、剥离前缀或转换规则。说明 MIME 注册状态不由本文保证。 | §2、§3.1、§14.2 |
| P1-1：出版与模式耦合 | PDF 的 `include_toc` 缺省固定为 `false`，`chapter_break` 固定为 `none`。书籍创建向导仍可建议目录和章节换页，但必须显式写入预设。切换模式不改变核心出版语义；不承诺产物字节相同。 | §11.2、§17 |
| P1-2：comic 基础效果 | 保留轻量基础实现；明确 `preview.layout=document` 属于补充能力，基础实现可以呈现与 `default` 相同的效果，但必须报告未支持的增强效果。 | §7、§10.1 |
| P1-3：设置补充地位 | 设置目录与主规范共同组成同修订草案；主规范内定义 S／R／V。保持标准能力 `mdk.settings-full@1`，不新增相互冲突的核心版本字段。 | §10.1、§19；设置目录 §1 |
| P1-4：合法封面 | 定义存在性、静态性、安全解码和有效尺寸／比例；要求支持静态 PNG／JPEG。其他格式须声明支持。封面居中完整缩放；允许保留 SVG 矢量或转换，不强制栅格化。 | §11.6 |
| P1-5：PDF 字体 | 明确 PDF 目标版本、实际文字字体必须嵌入、允许子集化，以及字体不可用／不能嵌入时的失败或显式有损处理。禁止把正文转路径或位图来绕过要求。 | §11.2 |
| P1-6：出版元数据 | 补 PDF XMP／兼容 Info／语言映射和 EPUB Dublin Core 映射；补 `dcterms:modified` 的生成时刻、UTC 格式和 `unique-identifier` 引用关系。作者按顺序映射；作品身份缺失不得静默编造。EPUB 声明封面时始终输出 `cover-image`，附加封面页另由开关控制。 | §11.3、§11.6 |
| P1-7：目标格式扩展 | 核心预设的 `format` 是 `pdf`／`epub` 闭合枚举。第三方目标使用自身 `extensions` 配置，不借未知枚举改变核心结构；仅影响所选预设的执行资格。 | §11.1、§11.4、§13 |
| P1-8：路径 | 补 C1 控制字符；新名称必须 NFC；保留已有名称的实际字节序列。Windows 保留名、尾部空格／点、名称冲突及长度作为可移植性问题，不粗暴禁止所有宿主限制对应的 ZIP 名称。双向控制字符须警告并提供转义显示。 | §9.1 |
| P1-9：安全强度 | 强制受限制的解析／渲染环境及明确安全结果；允许沙箱、受限解码器等实现方式，不要求所有媒体都必须采用同一种进程架构。 | §15 |
| P1-10：contents 根扩展 | 明确可选根级 `extensions` 及缺省值；空文件等价性仅适用于核心解释，不允许丢弃未知数据。 | §6.1 |
| P1-11：整数排序 | 保留整数顺序键。MDK 是持久工程快照，不在核心引入分数索引或协作合并协议。允许预留间隔；空位耗尽时同级保序重排，在同一次保存中提交，保持 ID 和对象关联。 | §6.3 |

## 2. 边界与一致性

| 报告条目 | 处理结果 | 规范位置 |
| --- | --- | --- |
| P2-1：锚点边界 | 引用块／列表中真正解析出的标题参加同一序列；删除线提取内部文本；代码块、HTML 块中的伪标题不参与。 | §8.2 |
| P2-2：GFM 数量 | 原文是选用三项，不是声称 GFM 总共三项。保留选择，明确排除另外两项，并说明 0.31.2 基线优先。 | §8.1 |
| P2-3：BOM | 明确这是 MDK 对单个开头 BOM 的预处理，不声称由 CommonMark 保证。未修改内容仍保留原字节。 | §4.1 |
| P2-4：六层残留 | 去掉固定六层叙述，保留任意格式深度与实现资源限额的区别；六级 Markdown 标题不受此修改影响。 | §6.3、§17 |
| P2-5：空 contents | 空核心目录可以带未知字段／扩展，其数据仍须保留。 | §6.1 |
| P2-6：颜色／图像 | 明确核心颜色不透明；解释宽度适配、尺寸上限与固有比例，不把图像裁切规则用于整篇正文。 | §10.1 |
| P2-7：基础字体语义 | 主规范直接定义 `body.font` 与 `body.font_family` 的关系，区分正常缺字后备与来源损坏。 | §10.1 |
| P2-8：局部修复 | 可解析设置允许修改独立字段；修改项及受影响的关联约束须合法，不引入新错误。未触及的独立历史错误保留并报告。语法损坏时禁止结构化编辑，整份替换仍须完整校验。 | §10.3、§14.2；设置目录 §19 |
| P2-9：未使用字体 | 保留已登记字体须完整交付的要求：基础交付承诺可继续编辑的自包含工程。出版只检查实际依赖；普通保存可保留未完成工程。这三个操作的资格不同。 | §14.1、§17 |
| P2-10：正文节点 | 集中定义 `kind=document`；空正文节点仍计入，只有分组节点的工程不能出版。 | §6.1、§11.1 |
| P2-11：导航位置 | 自动目录及 EPUB 导航规则移到共享范围，不再放在 PDF 小节。 | §11.1 |
| P2-12：诊断模型 | 枚举范围、状态、严重度、代码语法及通用代码；明确汇总优先级、定位字段和操作资格的关系。 | §2 |
| P2-13：ZIP 附加要求 | bit 11 和目录 STORE／CRC=0 明确为 MDK 附加约束，不再容易读作任意 ZIP 的要求。 | §3.2 |
| P2-14：URL 目标 | 解析后的包内目标必须是普通文件；目录不是合法链接／图片目标；严格区分缺失和类型错误。 | §9.2 |
| P2-15：扩展版本来源 | 工程和正文／节点对象由工程能力声明提供版本；预设的 `requires` 仅覆盖该预设的扩展，不外溢至其他对象。无声明数据不猜版本。 | §13.1 |
| P2-16：根扩展关联 | 根扩展关联工程及所属控制文件，对象扩展按 ID；派生工程时不猜测改写未知扩展内部身份。 | §13.4 |
| P2-17：切换模式保证 | 与 PDF 缺省修订配套，明确保证核心出版语义，不把它扩大为跨引擎的字节或分页一致。 | §11.2、§17 |
| P2-18：显示名 | 集中定义节点标题 → 正文标题 → 文件名回退链，分组必须有自己的标题。 | §6.2；设置目录 §17 |
| X-2、X-3、X-4：现行文档 | 为迁移记录、中文／英文 CLI、使用指南、现行导出、功能核对及规划文档标明 v1 适用范围，并在 v2 入口交代关系。未修改现有命令行为，也未创建 v1→v2 转换承诺。 | 主规范引言；相应文档开头 |
| X-5：缺少示例 | 补全四个可打包的解包工程、说明及一致性检查脚本；规范中的 16 个文件片段都有磁盘对应文件。 | §16；[示例目录](examples/v2/README.md) |
| X-6：小缺口 | 明确字面反斜线须在浏览器 URL 归一化之前拒绝；`first_single` 属于补充设置，基础实现须报告能力限制。 | §7、§9.2 |

## 4. 验证结果与边界

已运行 [示例检查脚本](../scripts/check-v2-examples.mjs)：

- 16 个规范文件片段与对应示例一致，其中 10 个 TOML 片段解析通过。
- 设置目录的 179 个字段均由模板覆盖：174 个活动字段和 5 个注释字体集字段。
- 四个工程分别包含 3／9／7／4 个文件；目录遍历、重复正文顺序、5 个正文活动链接及锚点检查通过。
- 生成四个测试 `.mdk`，复查物理前两项、STORE、UTF-8 标志及全部解压字节；另用 Python `zipfile`／原始头部解析独立验证所有 23 个条目的 CRC、名称、大小、位置和标志。
- 主规范、设置目录和示例说明的 17 个本地链接有效；47 条一致性用例位于一张完整表格中，新增条目没有脱离表格。

产物位于 `.test-artifacts/mdk-v2-examples/`；本目录被版本控制忽略，可由脚本重建。47 条规范用例是后续实现应覆盖的要求列表，不表示本次已实现并执行全部用例。

本次没有执行 PDF／EPUB 实际排版或应用 v2 读写测试；应用实现未改动。字体许可检查、安全解码、完整设置渲染、外部标准符合性及未知数据往返仍需要对应实现的测试，不能由这些受控示例检查代替。
