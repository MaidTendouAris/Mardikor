# MDK v1 修订版功能核对

依据 `MDK Format Specification v1.md` 的 **2026-11-03 修订版**。本次只修改应用及测试，不修改规范。旧文档中关于漫画示例冲突的说明已移除：所有 mode 的目录项均指向 Markdown，漫画按完整文稿编排。

## 模式与阅读预览

| 规范                                                    | 实现                                                                                                                                                                                        |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §3：default 是统一 Markdown 基础，book/comic 为用途预设 | 模式切换保留正文、目录项 ID、文件路径和未激活的设置，不隐式拆分或转换内容。                                                                                                                 |
| default 的编辑视图                                      | 按用户要求，00 模式仅预览当前文稿，以常规 Markdown 显示原有标题，自动目录放在左侧。可视化正文、预览及源码分栏预览随窗口宽度调整，忽略固定页宽和纸张边距，但保留这些设置原值供其他模式使用。 |
| §3.2：book 按 position 串联实际目录项                   | 阅读预览按精确数字段排序串联正文；虚拟分组不占正文单元，编号和标题目录只作用于视图。                                                                                                        |
| §3.2：comic 单元为目录项                                | 双页按实际条目两两配对，重复文件引用分别显示，奇数末项单独显示；rtl 只改变一对文稿的左右位置，不反转正文。多图、混排、纯文字和空文稿均保留 Markdown 语义。                                  |
| §6：稳定 ID、重复 path、六层位置、虚拟父分组            | Monaco 源码和文稿树双向更新；拖动整个子树、增减层级、菜单排序；重复 path 共享正文而保持条目独立，删除条目保留其他条目仍引用的文件。                                                         |
| §6.4、附录 A：延迟排序                                  | 阈值是应用偏好，不参与格式合法性。未同步目录保持脏标记；工程保存、自动保存和交付前提交一致快照。目录源码与可视化操作的冲突阻止提交。                                                        |

## 设置、保存和恢复

| 规范                                  | 实现                                                                                                                                                                                                  |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §1.2、15：控制 TOML 的 BOM 和整数类型 | 接受开头单个 UTF-8 BOM；schema 必须是 TOML 整数 1，拒绝 1.0 和字符串。未知整数/浮点字段类型在结构化修改中保留。                                                                                       |
| §7.3：精确默认值                      | 字号 16、行高 1.7、段间距 0.8、页宽 720、四边距 32；颜色按规范默认值。默认 include_meta=true、include_editor_state=false。                                                                            |
| §7.3：数值合法范围                    | 字号、行高、页宽为有限正数；段间距和边距非负，左右边距之和小于页宽。8–120 和 200 px 不作为合法性限制。主题不覆盖字体、布局或颜色字段。                                                                |
| §7.4：分级回退                        | 整份语法/schema 错误整体临时回退；单叶错误只回退该叶；错误表只回退该表；横向几何约束回退页宽与左右边距一组，保留上/下边距和其他合法字段。                                                             |
| §7、14、15：无效或未来 settings       | 基础内容仍可打开和保存，原 settings 字节不变；未来 settings 的未知结构只读，可显式删除。所有无效设置阻止严格交付。有效字段缺省仅在内存补齐，不由普通保存补写。                                        |
| §9：Monaco 源码与可视化               | Markdown/TOML/JSON/UTF-8 文本可编辑；无法无损往返的扩展语法使用源码，可视化只读。关键控制文件保存失败保留缓冲区及本地恢复草稿；合法日常编辑无需逐次确认。                                             |
| §9、15：原文保留                      | 未修改内容逐字节保留，包括 BOM、CRLF 和混合换行。Monaco 模型载入不产生假脏标记；实际编辑后使用其文件换行方式。结构化操作提示会重排 TOML 注释/空白，未知字段随稳定 ID 保留；仅修订实际变更的已知设置。 |
| §13：一致快照和磁盘冲突               | 正文、目录和设置通过单次快照提交；摘要版本不匹配时拒绝覆盖，缓冲区保留。临时文件 fsync 后重读全部 CRC/大小和结构，再原子发布。                                                                        |
| §6.4：关闭                            | 原生窗口提供保存并关闭、放弃、取消；保存失败保持窗口和输入。恢复草稿位于应用本地数据区，独立于 MDK，重新打开可恢复。                                                                                  |

在整体目录中新建的 Markdown 保持未编排；使用“加入文稿目录”显式建立条目并生成稳定 ID，“新增目录引用”可为同一文件添加独立条目。恢复同名缺失文件不会新增目录项。

“整体目录”提供真实文件树、折叠/筛选、新建文件和目录、重命名路径、删除、文本源码以及二进制预览/文件信息。Monaco 复用 VS Code 的编辑组件；不宣称兼容完整 VS Code 扩展宿主。

左侧“标题大纲”独立于 `contents.toml` 的文稿目录，实时解析活动编辑组缓冲区的 H1–H6/Setext 标题，排除代码示例，并可定位源码、可视化正文或预览。可视化格式工具栏位于正文滚动区域之外；移除顶部面包屑/格式标签栏及已打开文件标签栏，文件通过工程树切换。

Markdown 功能区按编辑、文本、段落和插入分组，提供六级标题、文本标记、三类列表与层级、引用、链接/图片属性、代码块语言、分隔线和硬换行。采用官方 Tiptap 表格扩展，支持 GFM 表格插入、行列增删、整列对齐和行内格式/图片；首行保持表头，单元格保持单段落，不产生需要 HTML 的合并或换行。图片按 CommonMark 行内节点处理，可与文字混排或放入表格。

正文右键菜单提供原生剪贴板、纯文本粘贴、复制为 Markdown、撤销重做、全选及链接/图片/表格上下文操作；支持 Shift+F10 和键盘导航。Monaco 保留原生右键菜单，新增 Markdown 格式命令及语法模板。模板覆盖自动链接、引用式链接/图片、Setext、缩进代码、转义和原始 HTML；引用定义、容器和原始 HTML 保持源码编辑，避免富文本序列化丢失。包括 `<br>` 在内的原始 HTML 仍按 §8.3 显示为文本，代码示例中的 HTML 不会误触发源码保护。

双栏编辑组可独立选择任意工程文件和源码/可视化/预览/设置视图。两栏打开同一文件时共享缓冲区，Monaco 共用文档模型与撤销历史；目录与标题大纲跟随活动组。所有可滚动正文视图（含原有源码预览分栏）按阅读进度双向同步，避免同步事件相互回传。多篇正文、目录和设置在一个快照内提交；多文件草稿独立于 MDK 保存，恢复时重新打开两个编辑组。文件重命名、删除和章节拆分后刷新各组的路径与内容。左右宽度可拖动；侧栏目录与标题大纲默认各占一半，横向分隔条支持拖动、方向键以及双击/Enter 恢复均分。

| §8、16：安全预览              | HTML 作为文本；图片先生成无 src 的占位再读取包内资源，不自动加载外部媒体或源码 data URL。危险协议禁用；外部导航仅由点击启用 HTTP(S)/mailto。活动 SVG 停止预览，保留源码/附件。                                                                                                                                                                                                                            |
| 拖放插入资源                  | 原生 File 由 preload 换取一次性路径授权；PNG/JPEG/GIF/WebP/BMP/AVIF/被动 SVG、MP3/WAV/OGG/FLAC/AAC/M4A、MP4/WebM、PDF 按扩展名白名单和文件特征验证。图片生成 Markdown 图片，音视频/PDF 生成附件链接。自动转存至分类 resources，计算相对 URL、编码文件名并处理重名；不支持、伪造、活动 SVG、混合非法批次和过期工程版本均不写入。资源与正文及待提交目录/设置一次原子保存，一次最多 16 个文件、合计 64 MiB。 |

| §10：删除与重命名             | 用户显式删除资源后允许保存缺失状态并报告。重命名会产生新的已知断链时拒绝，保留原路径并说明限制。未知扩展不自动执行、不自动清理。                                                                                                                                                                                                                                                                          |

## meta 数据

默认交付保留批注、持久数据和未知数据。`include_editor_state=false` 只剔除**整个文件已明确识别为可重建状态**的 `meta/editor-state.json`：当前识别 schema_version=1 的光标、打开标签、活动路径和滚动数据；含未知字段、未知嵌套内容、折叠结构或未知版本时保留整个文件。

`include_meta=false` 仍表示排除整个 meta。存在持久或未知数据时，预检列出具体剔除文件，要求用户确认本次交付；确认绑定源工程摘要，文件变化后需重新预检。筛选后再次检查本地引用，不能输出指向已剔除文件的新断链。普通保存始终保留用户未删除的 meta。

## ZIP 与容量边界

检查独立 payload 偏移、单卷/非 ZIP64、STORE/DEFLATE、UTF-8 名称、物理首项 mimetype、精确 MIME、CRC/大小、本地头/中央目录/descriptor 一致性、链接/设备属性、重复项、文件/目录及父目录冲突。中央目录排列不同不影响物理首项判定。

当前实现限额为单文件 64 MiB、容器/解压总量 256 MiB、10,000 项、解压检查时间 15 秒；DEFLATE 实际输出受硬上限约束。这些明确报告为实现支持范围，不作为 v1 格式容量界限。4 GiB 及以上资源属于 v1 本身不支持的范围。解包前检查宿主名称、大小写/Unicode 冲突、已存在目标及祖先链接，防止跨目录访问或覆盖。

## PDF / EPUB 出版转换

按新增需求开放 default / 单 Markdown 的 PDF，以及 book / comic 的 PDF / EPUB 3。MDK 容器交付保留；规范原文件未改动，出版配置使用 `settings.toml` 的 `extensions.mardikor.publication` 命名空间并复用已有排版、颜色和模式字段。配置面板涵盖作品信息、封面、字体、纸张与边距、分页、目录、页眉页脚、页码范围、缩放、灰度、标签/书签和 EPUB 布局选项。单 Markdown 配置仅保存在本机。说明见 `EXPORTING.md`。

PDF 固定工程字体与 SHA-256、出版源码/依赖锁定摘要、Electron/Chromium 版本及平台架构。正文和页面边距文字共用 Chromium 字体管线；元数据日期取自保存的出版日期，文档 ID 取自一致快照。字体缺失、字形不支持、嵌入限制或引擎不匹配会拒绝。修复 CFF 同形部首映射以保留源汉字的搜索/复制，只处理字体 ToUnicode 对象，不改变图像流。复制同一 MDK 到另一份隔离用户配置进行实际导出，验证 PDF SHA-256 相同；这不代替不同硬件机器的实测，跨机复现以匹配渲染版本与平台为条件。

EPUB 转换前执行容器、控制数据、引用、元数据、标题锚点、字体及资源检查；不支持的内容必须先处理。图片检查签名、解码前尺寸和实际解码，SVG 使用命名空间与图形元素白名单，原始 HTML 不隐式转换。固定页面溢出拒绝；comic 按完整实际条目处理单双页、RTL、重复文稿和奇数末项。生成后再次校验 OCF、XML、manifest、spine、导航和引用。转换不写回源 Markdown，不自动清理未编排内容或附件。

新增预检快照指纹和输出文件确认时摘要；源工程或已确认的输出在处理中改变时拒绝发布。输出通过临时文件、同步落盘和原子发布，失败保留原文件。单元用例覆盖配置与未知大整数保留、模式限制、元数据样式转义、字体字符、资源尺寸、带命名空间的活动 SVG、导航层级和损坏输出等；桌面用例 `test:publication` 通过真实 UI / preload / IPC 和 Chromium 验证导出。
