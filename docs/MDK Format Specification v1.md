# MDK 文件格式规范 v1

修订日期：2026-11-03

## 1. 定位

`.mdk` 是 Mardikor 的通用 Markdown 创作工程容器，用于保存可编辑、可恢复、可校验的项目内容。`default` 定义统一的基础格式；书籍、漫画等 mode 是在 default 基础上增加约束和默认设置的用途预设，其内容模型属于 default 的子集，正文始终是 Markdown。

v1 阶段 `.mdk` 也是主要交付/导出格式。Mardikor 只负责生成、保存、校验和交付 `.mdk` 工程文件；`.mdk` 到 EPUB、PDF、网页包、漫画包等其他格式的转换，等项目稳定后再纳入后续版本。

### 1.1 约束用语与适用范围

- “必须”“不得”“禁止”表示符合本规范的强制要求；“应”“推荐”表示允许有明确理由的例外；“可以”表示可选行为。
- 文件结构、字段、读写和校验规则是格式要求。第 9 节是 Mardikor 编辑器要求；附录 A 是非强制实现建议，不用于判定文件是否合法。
- 普通保存用于持久化进行中的工程；严格交付用于生成已通过结构和内容完整性检查的 `.mdk`。两者使用相同容器结构，具体处理见第 14 节。
- 文档中的示例服从字段规则；示例值只有在默认值表中明确列出时才是格式默认值。

### 1.2 文本编码

`contents.toml` 和 `settings.toml` 使用 UTF-8 编码及 [TOML 1.0.0](https://toml.io/en/v1.0.0) 语法；`schema_version` 是 MDK 字段结构版本，不是 TOML 语言版本。新建控制文件使用无 BOM 的 UTF-8；读取器必须兼容开头单个 UTF-8 BOM，在语法解析前跳过它，并在文件未修改时保留原始字节。LF 和 CRLF 均可接受。

Markdown 使用 UTF-8；JSON 扩展文件使用 UTF-8 JSON。未修改文件的编码标记和换行保留要求见第 9、15 节。`mimetype` 使用第 5 节规定的精确字节内容，不适用 BOM 容错。

## 2. 文件整体结构

`.mdk` 文件由两部分组成：

```text
byte 0-1      mode 文件头，两位 ASCII 十六进制数
byte 2...     ZIP payload
```

读取器必须先读取前 2 个字节作为 `mode`，再从第 3 个字节开始解析 ZIP payload。两字节前缀是 v1 的固定结构，前缀和 payload 之间没有空格、换行或填充字节。

ZIP payload 必须能够在剥离前缀后独立解析。所有 ZIP 内部偏移量均以 payload 的起点为基准，不包含两字节 `mode`；不得将以整个 `.mdk` 文件起点计算的偏移量写入 ZIP。读取器不得依赖 ZIP 库自动猜测或修正前缀。

`.mdk` 按本规范作为带前缀的容器处理，不保证通用 ZIP 工具直接打开整个文件。扩展名和 MIME 标识不能代替文件头及 payload 校验。

```text
project.mdk
├── [file header] mode = "00"
└── [zip payload]
    ├── mimetype
    ├── contents.toml
    ├── settings.toml
    ├── markdown/
    │   ├── 001.md
    │   └── ...
    ├── resources/
    │   ├── image/
    │   ├── video/
    │   ├── audio/
    │   ├── font/
    │   └── other/
    └── meta/
        ├── annotations.json
        └── editor-state.json
```

`settings.toml` 是正常工程推荐包含的设置文件，但不属于最小合法 `.mdk` 的必需文件。新工程可以不创建 `meta/`；已有 meta 数据的保留规则见第 11 节。

## 3. mode 文件头

`mode` 是 `.mdk` 文件最前部的用途预设标识，占用 2 个字节，必须是两位 ASCII 十六进制字符。它选择基于 default 的约束和默认设置，不选择另一种正文格式。

| mode | 用途 | 说明 |
|------|------|------|
| `00` | default | 统一的 Markdown 基础工程，定义全部 mode 共同遵守的内容、目录和资源规则。 |
| `01` | book | default 的书籍用途子集，提供线性阅读、标题目录及章节编号等约定和预设。 |
| `02` | comic | default 的漫画用途子集，提供以 Markdown 文稿为单位的图文预览、阅读方向及并排展示预设。 |
| `03`-`FF` | reserved | 预留给未来基于 default 的用途子集，不用于另立正文格式。 |

原 `mode = 01` 的 `novel` 映射废弃，统一更名为 `book`。

| 规则 | 要求 |
|------|------|
| 字节长度 | 固定 2 字节 |
| 编码 | ASCII |
| 字符范围 | `0-9`、`A-F`、`a-f` |
| 写入形式 | 必须使用大写十六进制，如 `00`、`01`、`02`、`0A` |
| 存储位置 | `.mdk` 文件最前 2 个字节 |
| 是否进入 ZIP | 否 |

读取器必须接受小写十六进制字符；写入器必须统一写入大写格式。合法但未知的值按第 15 节处理，不得在普通保存时自动改写为 `00`。

### 3.1 default 与用途子集

1. default 定义基础容器、目录项、Markdown 语法、资源引用和安全规则。book、comic 以及后续用途 mode 必须满足全部基础规则，只能增加明确的限制或提供默认设置，不得放宽基础要求。
2. 所有 mode 的 entries 均指向 Markdown 文稿，使用相同的语法和引用含义；不得因 mode 改用图片条目、分镜对象或另一套正文语法。同一段 Markdown 的基础解析结果不随 mode 改变。
3. 对任意合法的 book 或 comic 工程，只将 mode 改为 `00`，其 payload 必须仍是合法的 default 工程，ID、position、文件路径和内容均无须转换。预设的展示效果可以变化，未激活的模式设置仍须保留。
4. 从 default 切换到用途 mode 时，只检查该 mode 已明确规定的限制并应用缺省预设；不符合限制时说明原因，不得自动删除、改写或拆分正文。用户显式发起的内容转换属于独立编辑操作。
5. mode 默认值只填补缺省字段，不覆盖用户已显式写入的合法设置。模式限制必须在对应规范中明列；应用自身的工具布局、性能上限或偏好不能被当作额外的文件合法性条件。
6. 本版 book、comic 不增加 Markdown 语法禁用项，也不限定图片数量或要求文稿必须有图片。当前约定见第 3.2 节；不得仅凭“书籍”或“漫画”的名称推导未规定的内容限制。

### 3.2 v1 用途约定

| mode | 编排与预览约定 | 缺省预设 |
|------|----------------|----------|
| default | 接受全部基础合法 Markdown 工程；entries 表示通用文稿编排，不强制按章节或页面展示。 | 第 7.3 节的通用字段默认值。 |
| book | 阅读预览按 position 的基础顺序串联实际目录项；虚拟分组只组织目录。章节编号和标题目录只作用于视图，不重写 Markdown。 | `mode.book.toc_depth = 3`、`split_by_heading = false`、`chapter_numbering = true`。 |
| comic | 漫画预览以一个实际目录项作为一个逻辑展示单元；其中的文字、列表、图片等仍完整按 Markdown 解释。单页、双页是展示单元的排布方式，不是另一种存储结构。 | `mode.comic.reading_direction = "ltr"`、`page_fit = "contain"`、`spread_mode = "single"`。 |

comic 预览中，一个文稿包含多张图片时仍属于同一展示单元，不按图片数量自动拆页；纯文字或空文稿也合法。虚拟分组不占展示单元；不同目录项引用同一文件时，按各自的位置分别展示该文稿。

`spread_mode = "double"` 按实际目录项的阅读顺序两两配对，末尾不足一对时单独显示。`ltr` 时一对中的前项在左，`rtl` 时前项在右；不反转 contents 顺序，也不改变文稿内段落和行内内容的顺序。图片适应方式仅影响图像在预览区域内的展示，不得隐藏文稿中的文字或将整篇 Markdown 隐式转成图片。

## 4. ZIP payload

`mode` 后的所有字节构成 ZIP payload。ZIP payload 内部保存 `.mdk` 工程的实际内容。

| 项目 | 要求 |
|------|------|
| 起始位置 | `.mdk` 文件第 3 个字节 |
| 首项文件 | `mimetype` |
| `mimetype` 压缩方式 | STORE，不压缩 |
| 路径分隔符 | `/` |
| 路径形式 | 相对路径，不允许绝对路径 |
| 文件名编码 | UTF-8 |

### 4.1 ZIP 支持范围

ZIP 基础结构参照 [PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)，并遵守以下 v1 限定：

1. 使用单卷 ZIP，不使用分卷、ZIP64 或 ZIP 加密。超出标准 ZIP 字段容量时必须报告超限，不得截断数值或静默输出 ZIP64。
2. 普通文件仅允许 STORE（方法 0）和 DEFLATE（方法 8）。读取器必须支持这两种方法；不支持的压缩方式必须明确报错。
3. payload 必须以 `mimetype` 的本地文件头开始。“首项”按本地文件头在 payload 中的物理位置判定，不按库返回顺序或中央目录排序判定；中央目录可以使用不同顺序。
4. `mimetype` 的本地文件头必须直接提供 CRC 和大小，不使用 data descriptor。其他条目可以按 ZIP 规则使用 data descriptor；本地文件头、descriptor 和中央目录中的有效信息必须一致。
5. 写入器必须以 UTF-8 写入名称，并设置通用标志位 bit 11。读取器可以接受未设置该位的纯 ASCII 名称；其他名称必须明确采用 UTF-8，不得按本机代码页猜测。
6. 仅允许普通文件和目录条目，不允许表示符号链接、硬链接或设备文件的条目。目录条目可省略；如存在，名称以 `/` 结尾，去掉末尾 `/` 后按第 12 节校验。
7. 禁止重复文件名、重复目录名、同名文件与目录，以及将普通文件作为其他条目的父目录。禁止通过选择“第一项”或“最后一项”消解冲突。
8. 读取文件内容时必须校验实际解压大小和 CRC；CRC 用于发现损坏，不提供来源真实性保证。必须按第 16 节限制解压资源消耗。

实现自身的容量限制应明确报告为“超出实现支持范围”，不得将其混同于文件语法损坏。未知的安全普通文件按第 15 节保留。

v1 保留非 ZIP64 的范围：文件压缩前后大小及 ZIP 偏移受 32 位字段限制，条目总数受 16 位字段限制。单个 4 GiB（2^32 字节）及以上的资源不在 v1 支持范围内；实现必须在导入或交付前尽早报告超限，不能等到写入时截断内容。实现可以采用更低的安全容量限额，但必须明确区分实现限额与格式限额。

### 4.2 内部目录

推荐目录结构：

```text
zip payload
├── mimetype
├── contents.toml
├── settings.toml
├── markdown/
│   ├── 001.md
│   ├── custom-name.md
│   └── ...
├── resources/
│   ├── image/
│   ├── video/
│   ├── audio/
│   ├── font/
│   └── other/
└── meta/
    ├── annotations.json
    └── editor-state.json
```

| 路径 | 必需 | 说明 |
|------|------|------|
| `mimetype` | 是 | 固定 MIME 标识，必须是 ZIP payload 首项且 STORE 不压缩。 |
| `contents.toml` | 是 | 只控制目录结构。 |
| `settings.toml` | 否 | 正常工程推荐包含，用于样式、排版、预览、导出偏好等设置。 |
| `markdown/` | 否 | 保存 Markdown 正文文件。最小合法文件可不包含正文。 |
| `resources/image/` | 否 | 图片资源，如插图、漫画页面、封面图。 |
| `resources/video/` | 否 | 视频资源。 |
| `resources/audio/` | 否 | 音频资源。 |
| `resources/font/` | 否 | 字体资源。 |
| `resources/other/` | 否 | 其他资源或暂未分类资源。 |
| `meta/` | 否 | 持久扩展数据及可选编辑器状态。缺失合法，已有数据按第 11 节保留。 |

内部文件夹名、目录项语义和 Markdown 解析规则不因 mode 改变。模式差异仅体现为第 3 节明确的用途约定、附加限制及 settings 的缺省预设，不通过更换内部目录名或正文类型表达。

## 5. mimetype

`mimetype` 文件必须位于 ZIP payload 的第一项，且不得压缩或加密。

文件内容固定为：

```text
application/vnd.mardikor.mdk+zip
```

`mimetype` 文件内容必须恰好是上述字符串的 ASCII 字节序列，不得包含 BOM、空格、换行或结尾 NUL。校验时不得先 trim 再比较。

## 6. contents.toml

`contents.toml` 是 `.mdk` v1 的唯一必需 TOML 控制文件。它只控制目录结构，即工程中有哪些目录项、目录项如何排序、目录项指向哪个 Markdown 文件。

`contents.toml` 不控制样式、排版、预览、导出偏好、编辑器偏好、mode 预设或应用设置。工程设置及其缺省值按第 7 节解释；应用偏好与工程内容分别管理。

旧设计中的 `book.toml` 与 `theme.toml` 在 v1 中废弃。

### 6.1 最小 contents.toml

```toml
schema_version = 1
```

`schema_version` 必须是整数 `1`。`entries` 缺省等价于空数组；存在时必须是由表组成的数组。条目在 TOML 中的排列顺序不决定目录顺序。

### 6.2 完整 contents.toml 样例

```toml
schema_version = 1

[[entries]]
id = "01JZ8F8V7K9Y3M5P0Q2R6T1A4B"
path = "markdown/001.md"
position = "1"

[[entries]]
id = "01JZ8F92N6C4X8Q1V7W3D5E0K2"
path = "markdown/chapter-two.md"
position = "2"

[[entries]]
id = "01JZ8F9G8M2B6Y4T1N0C7P5Q3X"
path = "markdown/chapter-two-note.md"
position = "2.1"

[[entries]]
id = "01JZ8FA0V3D7K9Q2M5X1C8N4P6"
path = "markdown/chapter-two-extra.md"
position = "2.2"

[[entries]]
id = "01JZ8FAV5P0T2C9M6Q1X4D8N7Y"
path = "markdown/deep-note.md"
position = "2.2.1"

[[entries]]
id = "01JZ8FB8R7X5Q2M1N9C4V6K3D0"
path = "markdown/final.md"
position = "3"
```

### 6.3 entries 字段

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 稳定 ID，由写入器生成和维护，不作为默认显示名称。 |
| `path` | string | 是 | 目录项指向的 Markdown 文件路径，必须位于 `markdown/` 下并以 `.md` 结尾。 |
| `position` | string | 是 | outline-path 目录位置，如 `1`、`2.1`、`2.1.3`。 |

`id` 规则：

1. `id` 必须是非空且不全为空白的字符串，在当前工程全部 entries 中唯一。比较区分大小写，不进行 trim、大小写转换或 Unicode 归一化。
2. `id` 不作为编辑器默认显示名称；源码模式和诊断工具可以显示 ID。
3. `id` 必须稳定；文件重命名、拖拽排序、position 变化时不得改变。
4. 推荐使用 ULID、UUID v7，或其他足够稳定且低碰撞概率的 ID。
5. `id` 标识目录项，不标识路径或文件内容。复制为新的目录项时必须分配新 ID；删除后新建条目不得主动复用已删除条目的 ID。

`path` 规则：

1. `path` 必须是以 `markdown/` 开头、以小写 `.md` 结尾的工程根目录相对路径，遵守第 12.1 节；允许子目录。所有 mode 均遵守此规则。
2. `markdown/` 下作为正文内容的文件只接受 `.md`。
3. `.md` 文件允许用户自行命名。
4. 创建新 Markdown 文件时，编辑器默认命名为 `001.md`、`002.md` 等递增名称；若文件名已存在，编辑器应自动避让。
5. 编辑器显示名称默认使用 `.md` 文件名去掉扩展名。
6. 多个目录项可以引用同一个 `path`，但 `id` 和 `position` 必须不同。编辑该文件会影响所有引用它的目录项；删除目录项不得默认删除仍被其他目录项引用的文件。
7. 目标文件缺失属于内容不完整，按第 14 节报告和处理。不得自动创建空文件覆盖原本需要恢复的内容。
8. 未列入 entries 的 Markdown 文件作为未编排内容保留，不自动加入阅读顺序，也不得在保存或交付时静默清理。
9. 漫画文稿使用普通 Markdown 引用 `resources/image/` 中的图片；一个文稿可以包含多张图片及其他 Markdown 内容，也可以不含图片。v1 不允许目录项直接指向图片；展示单元约定见第 3.2 节，合法示例见第 18.2 节。

`position` 规则：

1. `position` 使用 outline-path 形式，例如 `1`、`2`、`2.1`、`2.1.3`。
2. 每段只使用 ASCII 十进制数字，首位为 `1` 到 `9`；禁止前导零、正负号和空白。完整语法为 `^[1-9][0-9]*(\.[1-9][0-9]*){0,5}$`。
3. 最多 6 段。这是 v1 的目录层级限制，独立于正文的 `h1` 到 `h6`；读取器不得因目录层级而自动改写正文标题等级。
4. `position` 决定编辑器左侧文件树的显示顺序和层级。
5. 不允许两个 entries 使用相同 `position`。
6. 排序时按数字段逐级精确比较，不按整个字符串比较。例如 `2.10` 排在 `2.2` 之后。比较不得因浮点数精度丢失而把不同段判为相等；可逐段按数字长度及字典序比较。
7. 父子关系由 `position` 直接表达，不依赖相邻条目推断。
8. 当一个位置是另一个位置的完整段前缀时，父级排在后代之前，例如 `2` 排在 `2.1` 之前。同级编号可以不连续，如 `1`、`3` 合法。
9. 允许父位置没有对应目录项，如仅存在 `2.1`。读取器必须构建位置 `2` 的虚拟分组；该分组没有正文和目录项 ID，不要求创建占位 Markdown 文件。

排序示例：

```text
1
2
2.1
2.2
2.2.1
3
```

### 6.4 目录变更与持久化

编辑器左侧文件树是 `contents.toml` 的可视化编辑界面。用户不需要直接编辑 TOML 源文件。

1. 目录移动必须保持条目 ID；移动一个父节点时，应保持其后代的相对顺序和父子关系，除非用户明确选择改变它们。
2. 实现可以合并连续排序操作并延迟写入，但必须标记待保存状态。
3. 用户执行工程保存或交付时，必须将当前确认的目录、正文及资源变更作为同一快照写入，不得输出旧目录配新正文的混合状态。
4. 源码编辑与可视化目录编辑必须处理冲突，不得相互静默覆盖。关闭时有待保存变更，必须提供保存、放弃或取消关闭的选择，或已建立可靠的恢复记录。

延迟写入阈值和“更新目录”按钮属于实现选择，见附录 A。

## 7. settings.toml

`settings.toml` 用于控制样式、排版、预览、导出偏好和 mode 用途预设。模式设置只作用于基础 Markdown 工程的展示和操作偏好，不定义独立正文模型。正常 `.mdk` 工程推荐包含该文件；最小合法 `.mdk` 可以不包含。

读取器不得因为缺少 `settings.toml` 而拒绝打开 `.mdk` 文件。缺失字段按第 7.3 节补齐；默认值只用于解释，不要求在普通保存时将缺省字段或整个缺失文件写回工程。

### 7.1 settings.toml 样例

```toml
schema_version = 1

[appearance]
theme = "default"
font_family = "system"
font_size = 16
line_height = 1.7
paragraph_spacing = 0.8

[layout]
page_width = 720
margin_top = 32
margin_bottom = 32
margin_left = 32
margin_right = 32

[colors]
text = "#1f2933"
background = "#ffffff"
link = "#2563eb"
quote = "#64748b"

[preview]
show_title = true
show_toc = true
render_containers = true

[export]
default_target = "mdk"
validate_before_export = true
include_meta = true
include_editor_state = false
preserve_source_names = true

[export.mdk]
package_mode = "portable"
overwrite_existing = false
normalize_paths = true

[mode.book]
toc_depth = 3
split_by_heading = false
chapter_numbering = true

[mode.comic]
reading_direction = "ltr"
page_fit = "contain"
spread_mode = "single"
```

### 7.2 settings.toml 规则

1. `settings.toml` 必须包含 `schema_version`，如果该文件存在。
2. v1 的 `settings.toml.schema_version` 必须是整数 `1`。
3. 除 `schema_version` 外，所有设置字段和表都允许缺省。
4. 已知字段存在时必须满足第 7.3 节的类型与范围。数值字段禁止 NaN、正负无穷；不得将字符串或布尔值自动转换为数值。
5. `contents.toml` 不得复制 `settings.toml` 中的设置字段。
6. 遇到无效或不支持的 settings 时按第 7.4、14、15 节降级处理。内存中的回退设置不得静默替换原始文件；只有用户实际修复设置时才写入修复结果。
7. 未知字段按第 15 节保留。支持更多字段的实现不得要求其他 v1 读取器理解这些扩展才能打开基础工程。

### 7.3 字段定义与默认值

下表的 `number` 接受 TOML 整数或浮点数；`integer` 仅接受 TOML 整数。所有布尔字段仅接受 `true` 或 `false`。

| 字段 | 类型与范围 | 缺省值及含义 |
|------|------------|--------------|
| `appearance.theme` | 非空 string | `"default"`；正文展示预设名。未知主题回退到 default 并保留原值。 |
| `appearance.font_family` | 非空 string | `"system"`；系统默认字体。也可以是字体族名，或 `resources/font/` 下的工程根目录相对路径。 |
| `appearance.font_size` | number，大于 0 | `16`，CSS px。 |
| `appearance.line_height` | number，大于 0 | `1.7`，相对于当前字号的无单位倍数。 |
| `appearance.paragraph_spacing` | number，不小于 0 | `0.8`，em，表示相邻段落之间的额外间距。 |
| `layout.page_width` | number，大于 0 | `720`，CSS px，页面总宽度，含左右留白。 |
| `layout.margin_top` / `margin_bottom` / `margin_left` / `margin_right` | number，不小于 0 | 均为 `32`，CSS px，页面四侧留白；左右之和必须小于 page_width。 |
| `colors.text` / `background` / `link` / `quote` | string，`#RGB`、`#RGBA`、`#RRGGBB` 或 `#RRGGBBAA` | 依次为 `"#1f2933"`、`"#ffffff"`、`"#2563eb"`、`"#64748b"`。 |
| `preview.show_title` | boolean | `true`；是否展示每篇正文的首个一级标题，不修改原文。 |
| `preview.show_toc` | boolean | `true`；是否展示阅读目录。 |
| `preview.render_containers` | boolean | `true`；是否按第 8.2 节渲染容器；关闭时显示原始容器标记及内容，不删除文本。 |
| `export.default_target` | string，v1 为 `"mdk"` | `"mdk"`。其他值作为不支持的扩展偏好保留，不执行其他格式导出。 |
| `export.validate_before_export` | boolean | `true`；控制是否提前展示预检报告，不得关闭最终交付的强制检查。 |
| `export.include_meta` | boolean | `true`；是否交付 meta 数据。false 表示从交付副本中排除整个 meta 目录；剔除持久或未知数据前必须按第 11 节明确提示并确认。普通保存不受此字段影响。 |
| `export.include_editor_state` | boolean | `false`；include_meta 为 true 时，是否同时保留已识别的可重建编辑器状态。未知数据和批注不属于可自动剔除状态。include_meta 为 false 时本字段不生效。 |
| `export.preserve_source_names` | boolean | `true`；保留内部源文件名。false 允许交付副本重命名，但必须同步全部受影响的引用；无法保证时保留原名并提示。 |
| `export.mdk.package_mode` | string，v1 为 `"portable"` | `"portable"`；正文及本地依赖包含在包内。不支持的值保留并报告，不据此输出另一种容器。 |
| `export.mdk.overwrite_existing` | boolean | `false`；允许交付操作覆盖已存在目标文件的偏好，不影响普通保存。 |
| `export.mdk.normalize_paths` | boolean | `true`；允许交付时规范化可安全改写的引用。false 不豁免路径安全和存在性检查。 |
| `mode.book.toc_depth` | integer，1–6 | `3`；书籍预览中正文标题目录的最大标题等级，不改变 entries 的目录层级。 |
| `mode.book.split_by_heading` | boolean | `false`；是否启用按标题拆分操作，不得在普通打开、保存或交付时隐式拆分。 |
| `mode.book.chapter_numbering` | boolean | `true`；是否展示自动章节编号，不修改原文或文件名。 |
| `mode.comic.reading_direction` | string，`"ltr"` 或 `"rtl"` | `"ltr"`；文稿展示单元的排布方向，按第 3.2 节解释，不改变正文顺序。 |
| `mode.comic.page_fit` | string，`"contain"`、`"cover"` 或 `"width"` | `"contain"`；图像在预览区域内完整适应、填充裁切或适应宽度，不改变 Markdown 内容模型。 |
| `mode.comic.spread_mode` | string，`"single"` 或 `"double"` | `"single"`；按第 3.2 节单独或成对展示 Markdown 文稿，不按图片数量拆页。 |

工程设置的解释优先级为：工程中显式设置的合法字段 > 当前 mode 已规定的缺省预设 > default 的基础默认值。本表中通用字段的值是基础默认值，`mode.book.*` 和 `mode.comic.*` 的缺省值分别属于对应预设；本版 book、comic 不另行覆盖通用字段默认值。局部表按字段合并，不因某个字段存在而取消同表其他字段的默认值。同一规则适用于普通工程和交付副本，不依赖文件的来源或本机用户偏好。

应用偏好可以用于初始化新工程，但希望持久化的取值必须明确写入工程设置。交付不得隐式写入本机字体名、路径或用户偏好。主题不得改变本表中字体、布局和颜色字段的解析结果；要使用预设中的这些值，应将其保存为工程设置。主题仍可控制本表未定义的其他展示细节。

本地无障碍或阅读显示覆盖可以作用于当前视图，但必须与工程设置区分，不得静默修改文件或影响交付检查。

只有与文件头匹配的 mode 预设设置自动生效；其他 mode 设置仍保留，default 也接受含这些设置表的合法工程。模式切换可以改变缺省展示效果，但不得自动将新预设值写入原本缺省的字段。字体资源路径按第 12.1 节解析；字体族不可用时回退到 system，不得把字体族名作为本地文件路径读取。

字号和页宽的界面建议范围见附录 A。格式不以 8–120 px 或 200 px 作为合法性界限；实现不能安全渲染某个合法数值时，应提示渲染能力限制或提供临时缩放显示，保留原值，不得将工程误判为结构损坏。

### 7.4 无效设置的回退范围

1. settings 缺失时，按第 7.3 节解析缺省值；文件存在但 TOML 语法错误，或 schema_version 缺失、类型无效、版本不支持时，整份 settings 不参与解释，临时使用当前 mode 预设与基础默认值。
2. TOML 和 schema 合法时，按字段检查已知值。一个叶字段的类型、枚举或数值范围错误，只回退该字段，不影响其他合法显式字段。例如 font_size 非法时，合法的 colors 和 page_width 继续生效。
3. 已知表本身类型错误时，如 `appearance = "invalid"`，该表下的全部已知字段按缺省处理；其他表仍正常解析。未知字段不因未被识别而视为非法，原始数据仍须保留。
4. 先完成单字段回退和缺省补齐，再检查关联约束。如果 `layout.margin_left + layout.margin_right >= layout.page_width`，将 page_width、margin_left、margin_right 三个字段作为一组，临时回退到当前 mode 对该组的完整默认值；本版为 `720`、`32`、`32`。margin_top、margin_bottom 和其他设置保持各自的有效值。
5. 以上回退仅用于打开和预览，必须报告错误字段及使用的临时值；不得据此自动修复或覆盖原文件。普通保存可以保留未修改的原 settings 并保存其他内容，严格交付仍须修复无效设置或由用户显式移除该可选文件。
6. 未激活 mode 表中的已知字段也要校验和报告，但其回退不影响当前 mode 的有效设置。新建或主动修改 settings 时，全部已知字段及关联约束必须合法，不能把只在内存中执行的回退当作成功修复。

## 8. markdown

`markdown/` 保存 Markdown 正文文件。

| 项目 | 要求 |
|------|------|
| 编码 | UTF-8 |
| 扩展名 | `.md` |
| 路径 | 必须位于 `markdown/` 下 |
| 文件命名 | 用户可自定义；创建时默认 `001.md` |
| 引用资源路径 | 推荐使用相对路径，如 `../resources/image/cover.png` |

### 8.1 语法基线

v1 以 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/) 为基础，采用 [GFM 0.29-gfm](https://github.github.com/gfm/) 的删除线、任务列表和表格扩展。仅采用明确列出的 GFM 扩展；基础语法存在差异时以 CommonMark 0.31.2 为准。原始 HTML 按第 8.3 节安全展示。

这套语法同时适用于 default、book 和 comic。模式预览可以改变文稿的排布和视图，但不得重新解释图片语法、隐去普通 Markdown 内容，或要求使用模式独有语法才能读取正文。

符合本规范的 Markdown 预览器必须支持以下基础内容；仅负责打包或源码编辑的工具不要求提供渲染器：

| 元素 | 说明 |
|------|------|
| 标题 | `#` 到 `######` |
| 段落 | 普通正文 |
| 粗体 / 斜体 / 删除线 | 基础行内样式 |
| 行内代码 | 使用反引号 |
| 有序 / 无序列表 | 基础列表 |
| 任务列表 | GFM 风格任务列表 |
| 表格 | GFM 表格 |
| 引用 | `>` |
| 分隔线 | `---` |
| 代码块 | fenced code block |
| 图片 | Markdown 图片语法 |
| 链接 | 普通链接、引用式链接和自动链接；路径解析见第 12.2 节。 |
| 自定义容器 | `:::note`、`:::warning`、`:::tip` |

未知或暂不支持的语法必须保留原文。未编辑的 Markdown 文件不得仅因打开、预览或保存其他文件而重新序列化；无法保证往返保留的可视化编辑器必须将相应内容设为只读或要求使用源码模式。

### 8.2 自定义容器

1. 开始行由至少 3 个冒号、类型名 `note` / `warning` / `tip` 和可选行尾空白组成。冒号与类型名之间可以有空格或制表符；v1 不定义标题、属性或其他参数。
2. 开始行和结束行可以有 0–3 个前导空格。结束行仅包含不少于对应开始行数量的冒号及可选行尾空白。
3. 容器内容按 Markdown 解析。允许嵌套；外层必须使用比内层更多的冒号，结束行先关闭当前最内层匹配的容器。
4. 代码块中的冒号不作为容器定界符；列表或引用内的定界符在移除其块容器前缀后识别。
5. 未知类型、未知参数或未闭合容器作为普通 Markdown 文本保留，不自动补全或删除标记。

```markdown
::::note
这里是提示内容。

:::tip
这里是嵌套提示。
:::
::::
```

### 8.3 HTML 与外部内容

v1 基础预览必须将正文中的原始 HTML 作为文本展示，不执行其中的脚本、事件处理器或嵌入对象。扩展渲染器可以提供受限 HTML 支持，但必须经过净化和隔离，且不能据此改写源码。SVG、媒体和链接的安全处理见第 16 节。

外部 HTTP(S) 链接不是包内文件；网络不可达不得被报告为包内资源缺失。预览默认不得自动请求外部媒体；开启外部加载必须由用户控制。严格交付中正文展示所依赖的图片、音视频等必须已纳入包内；普通导航超链接可以仍指向外部网站。

## 9. 源码编辑能力

Mardikor 编辑器必须提供源码模式。源码模式用于直接查看和编辑 `.mdk` 内部的纯文本文件，包括但不限于：

| 类型 | 示例 |
|------|------|
| Markdown 正文 | `markdown/001.md`、`markdown/custom-name.md` |
| TOML 控制文件 | `contents.toml`、`settings.toml` |
| JSON 扩展文件 | `meta/annotations.json`、`meta/editor-state.json` |
| 其他纯文本 | `.txt`、`.json`、`.toml`、`.md` 等可安全按 UTF-8 文本读取的文件 |

源码模式规则：

1. 源码模式必须保留未修改文件的原始字节，包括 BOM、换行和缩进。编辑后应保留原有格式；不得丢弃未知字段或未编辑的未知语法。结构化编辑不能保留注释、空白布局时，应提示该限制并提供源码编辑方式。
2. 编辑 `.md` 时，应允许在可视化编辑和源码编辑之间切换。
3. 编辑控制 TOML 时，必须在提交到工程前执行语法和字段校验。校验失败必须保留编辑缓冲区或恢复草稿，不得将非法控制文件覆盖进工程。切换视图可以显示错误或暂存缓冲区，不得静默丢弃输入。
4. 编辑 `contents.toml` 时，必须校验 `id`、`path`、`position` 规则。
5. 编辑 `settings.toml` 时，缺省字段仅在内存中按第 7.3 节补齐；不自动把回退值写回源文件。
6. 对二进制资源文件，源码模式不得以文本方式强行打开；应显示资源预览或文件信息。
7. 对关键文件必须显示校验诊断；合法的日常编辑不要求每次确认。修改固定 `mimetype` 内容、删除必需文件或破坏目录结构必须被校验阻止。

源码模式是编辑器能力，不改变 `.mdk` 文件结构。

## 10. resources

`resources/` 保存工程使用的媒体和附件，包括二进制文件及 SVG 等文本资源。资源目录按媒体大类固定命名，不因 `mode` 改变。

| 路径 | 说明 |
|------|------|
| `resources/image/` | PNG、JPEG、WebP、GIF、SVG 等图像。 |
| `resources/video/` | MP4、WebM 等视频。 |
| `resources/audio/` | MP3、AAC、FLAC、WAV、OGG 等音频。 |
| `resources/font/` | TTF、OTF、WOFF、WOFF2 等字体。 |
| `resources/other/` | 其他附件或暂未分类资源。 |

读取器应结合扩展名和实际内容识别格式；未知格式可作为不透明附件保留，不得为了识别而执行文件。打开、保存和交付时应检查已知的本地引用；缺失引用按第 14 节处理，不得阻止普通正文保存。

引用检查必须使用实际语法解析结果，覆盖 Markdown 行内和引用式图片、链接以及 settings 中的字体资源路径，排除代码示例和外部导航链接。支持其他引用语法的扩展必须将其已知依赖纳入检查。未知扩展可能引用资源，因此“未发现引用”不能作为自动删除文件的依据。

重命名、移动或交付时改名必须同步所有已知引用；遇到无法判断的扩展依赖，应保留原路径或明确提示操作限制。不能保证同步时不得静默生成断开的引用。主动删除资源造成的缺失允许作为未完成工程状态保存，并须报告受影响的引用。

## 11. meta

`meta/` 不是必需目录，缺失不影响基础打开。目录可选不表示其已有内容可以全部丢弃。

| 文件或数据 | 性质 | 保存和交付规则 |
|------------|------|----------------|
| `meta/annotations.json` | 批注、评论、标记等持久用户数据 | 普通保存和默认交付必须保留；从交付副本剔除时必须显式提示并确认。 |
| `meta/editor-state.json` 中已识别的光标、打开标签、折叠状态等 | 可重建的编辑器状态 | 普通保存可以更新；交付时由 include_meta 和 include_editor_state 共同控制。 |
| 未知文件、未知字段或未知版本的扩展数据 | 性质未知，按持久数据处理 | 不解释、不执行，原样保留，不得默认清理。 |

1. v1 不规定批注 JSON 的具体字段结构；实现使用自己的版本化结构，并应使用目录项 ID 或其他稳定标识关联内容。不了解其结构的读取器必须按不透明数据保留。
2. 在保留 meta、仅剔除编辑器状态时，只有确认整个状态文件均为可重建状态才可省略该文件。包含未知字段或持久数据时，必须保留文件，或只删除已识别的可重建字段并保留其余数据。
3. 用户可以显式选择删除批注或其他持久扩展数据，但操作必须说明会删除哪些内容。普通保存、清理缓存和默认交付不得隐含执行该删除。
4. 可以保存在本机配置中的光标、窗口等状态应优先保存在本机；需要跨设备携带的批注不得仅因属于 meta 就移出工程。

交付筛选规则如下；它们只作用于交付副本，不删除源工程数据：

| include_meta | include_editor_state | 交付副本中的 meta |
|--------------|----------------------|-------------------|
| true | true | 保留全部 meta。 |
| true | false | 保留批注、其他持久数据及未知数据；仅可剔除已识别的可重建状态。此组合为本版默认。 |
| false | 任意值 | 排除整个 meta 目录。只要其中含有持久或未知数据，必须列出剔除范围，并由用户确认本次交付选择；未确认则不得生成该删减副本。 |

`include_meta` 保留“是否交付 meta 数据”的原义。不能将旧工程显式保存的 false 改解释为“仍交付批注”；也不能仅凭文件中的 false 推定用户已确认本次剔除持久数据。缺省值及新增字段的兼容规则见第 15.4 节。

筛选后必须重新检查交付副本的已知引用，引用了被剔除 meta 文件的内容须先由用户处理，不能输出新的断链。批注的保留和剔除规则适用于全部 mode，不能被用途预设覆盖。

## 12. 路径规范

### 12.1 包内文件名与控制字段路径

ZIP 条目名、`entries[].path` 和指向包内字体的设置使用工程根目录相对路径，不是 URL，禁止对这些值做百分号解码。

| 规则 | 要求 |
|------|------|
| 路径类型 | 相对路径 |
| 分隔符 | `/` |
| 绝对路径 | 禁止 |
| 路径段 | 禁止空段、`.` 和 `..` 段；文件路径不得以 `/` 结尾，目录条目例外见第 4.1 节。 |
| 禁止字符 | 反斜线、冒号、U+0000–U+001F 及 U+007F；禁止盘符、UNC 和设备路径。 |
| 空路径 | 禁止；可选字段应省略，不以空字符串代替合法路径。 |
| 大小写 | 区分大小写，精确匹配，不按宿主文件系统的比较方式查找。 |
| Unicode | 按实际字符序列精确匹配；读取时不得自动归一化名称并合并条目。 |

新建名称推荐使用 Unicode NFC，并避免仅大小写或 Unicode 归一化形式不同的文件名。读取已有文件时必须保留实际名称；无法在宿主文件系统上安全表示的名称应在包内或虚拟文件系统中处理，解包时报告冲突，不得自动覆盖。Windows 保留名称、末尾点或空格等应作为可移植性问题提示。

### 12.2 Markdown 中的引用

1. 包内相对引用以所在 Markdown 文件的目录为基准解析；例如 `markdown/001.md` 中的 `../resources/image/cover.png` 解析为 `resources/image/cover.png`。
2. 引用可以包含 `.` 和 `..` 路径段，但逐段解析时不得越过工程根目录。判断必须基于路径段，不能依赖简单的字符串前缀匹配。
3. 先按 Markdown 语法获得链接目标，再区分 URL 的路径、查询和片段。查询与片段不参与包内文件名匹配；路径部分为空时指向当前文件，例如 `#片段`，不是缺失文件。锚点存在性可以另行诊断。
4. URL 路径按 `/` 分段后，每段仅执行一次 UTF-8 百分号解码。无效编码或解码后含 `/`、反斜线、冒号或控制字符的段必须拒绝；解码得到的 `.`、`..` 必须参与根目录边界检查，不得重复解码。
5. 文件名中的 `%`、`#`、`?` 等 URL 特殊字符必须在引用中正确编码。例如包内文件名 `a#b.png` 使用 `a%23b.png` 引用；包内文件名本身不因此改名。
6. 包内引用不得以 `/` 开头；非空路径不得包含重复或末尾分隔符产生的空段。解析后的目标必须满足第 12.1 节，v1 不将目录当作本地文件引用目标。外部 URL 与包内路径分开处理，不得映射为宿主文件路径；允许的行为见第 8.3、16 节。
7. 不安全的引用必须停止解析和加载，并显示诊断；它仍可作为源码文本保存，不得执行访问包外文件的操作。严格交付必须处理不安全的活动引用。

### 12.3 解包边界

落地到文件系统前，必须校验全部路径、大小写或归一化冲突、文件与目录冲突，以及实际目标路径是否仍位于选定解包目录内。不得跟随包内链接或目标目录中已有的符号链接、重解析点逃逸该目录；冲突必须报错或由用户指定新的安全目标。

## 13. 读写流程

### 13.1 读取流程

1. 读取文件前 2 个字节。
2. 校验 `mode` 是否为两位十六进制数。
3. 从第 3 个字节开始，以 payload 为独立字节区间解析 ZIP；先检查目录、声明大小、条目数量和支持范围，再按限额读取内容。
4. 校验 ZIP payload 的物理首项是否为未压缩的 `mimetype`，并检查路径、重复条目及本地头与中央目录的一致性。
5. 校验 `mimetype` 内容。
6. 读取并解析 `contents.toml`。
7. 如存在 `settings.toml`，按第 7.4、15 节的明确范围解析或回退；如不存在，则按第 7.3 节解析缺省设置。
8. 根据 `contents.toml` 构建目录树。
9. 根据目录项、Markdown 和已知扩展引用检查内容完整性；缺失引用以可恢复诊断呈现，不妨碍基础打开。
10. 以 default 基础内容模型加载工程，再应用已知 mode 的约定、限制和预设视图；未知 mode 的限制标记为未验证。

### 13.2 普通保存与严格交付

1. 获取一致的工程快照，处理源码和目录变更冲突，将已确认的目录排序同步到 `contents.toml`。
2. 收集正文、资源和扩展数据。仅更新用户实际修改的设置，不因回退默认值而覆盖无效或未知版本的 settings。
3. 普通保存保留所有未被用户删除的内容；严格交付按第 7、11 节生成独立副本，不修改当前工程中的源文件名或批注。
4. 执行第 14 节对应操作的检查。普通保存允许内容暂不完整；严格交付必须通过规定的结构、设置和已知依赖检查。
5. 构造独立 ZIP payload，确保 `mimetype` 是物理首项且使用 STORE；所有 ZIP 偏移量从 payload 起点计算。
6. 在目标目录创建唯一临时文件，先写入两位大写 `mode`，再原样追加 ZIP payload。不得先截断或覆盖已有工程。
7. 完成写入并刷新数据到存储设备，重新打开临时文件，验证容器、控制数据和各文件的 CRC、大小，并执行与本次操作一致的检查。
8. 全部成功后，通过同一文件系统的原子替换发布目标文件；交付未授权覆盖已有目标时，必须使用不会覆盖既有文件的发布方式。平台无法提供所需保证时必须保留原文件并报告限制，不得以“先删除原文件再重命名”代替。
9. 任一步骤失败必须保留原工程和未保存的编辑状态；仅在替换成功后清除对应的待保存标记。清理临时文件不得影响原文件。

保存过程中如发现磁盘上的源工程已被其他进程修改，必须报告冲突，不得静默覆盖。实现可以通过独占锁或加载时记录的文件标识与内容摘要检测；仅检查文件名不足以判断是否仍为同一版本。

## 14. 完整性校验

校验结果必须区分结构错误、内容不完整、设置降级和非阻断提示，不能仅凭单一 Error 标记决定所有操作是否允许。“允许保存”不代表“通过严格交付校验”。

| 情况 | 打开 | 普通保存 | 严格交付 |
|------|------|----------|----------|
| mode 字节不是两位 ASCII 十六进制数，或 payload 边界错误 | 拒绝正常打开，可进入受限修复 | 修复前禁止覆盖原文件 | 禁止 |
| 合法但未知的 mode | 警告，按 default 基础规则打开 | 保留 mode 和未知数据，遵守第 15 节的编辑限制 | 可校验基础内容，必须声明该 mode 的附加约束未验证；不得声称已通过其模式校验 |
| 内容符合 default，但不满足目标 mode 明文规定的附加限制 | 保留内容并报告模式限制问题 | 允许保存未完成工程，或由用户选择切回 default；不自动改写正文 | 必须满足目标 mode 限制，或由用户显式选择以 default 交付 |
| 不支持的 ZIP 特性、损坏头、CRC 或实际大小不符 | 拒绝正常打开，报告原因 | 修复前禁止覆盖 | 禁止 |
| 不安全包内路径、重复条目或文件目录冲突 | 拒绝；不得执行危险解包 | 修复前禁止覆盖 | 禁止 |
| 缺少 mimetype、不是物理首项、非 STORE 或内容不精确匹配 | 拒绝正常打开，可修复 | 修复前禁止覆盖 | 禁止 |
| 缺少 contents、语法错误、schema 无效或版本不支持 | 不作为可编辑 v1 打开；可以只读恢复 | 禁止以 v1 覆盖原文件 | 禁止，迁移或升级后再处理 |
| entries 类型错误；必需字段缺失、类型错误；空白或重复 ID；非法路径；position 格式错误、重复或超过 6 层 | 不作为正常目录加载，可修复 | 修复前禁止提交错误控制数据 | 禁止 |
| entries 目标 Markdown 不存在 | 允许，显示缺失条目 | 允许并提示工程不完整 | 禁止，修复引用或显式删除条目 |
| 已知本地资源引用不存在 | 允许，显示占位和诊断 | 允许并提示缺失引用 | 禁止，补齐或修改引用 |
| 活动引用越界或使用禁止协议 | 保留源码，禁用访问并报告 | 允许保存文本，不允许执行访问 | 禁止，修正或移除活动引用 |
| 展示依赖使用外部 HTTP(S) 媒体 | 允许，默认不自动加载 | 允许 | portable 交付前必须转为包内资源；导航超链接除外 |
| settings 缺失或合法字段缺省 | 正常打开，解释默认值 | 允许，不强制补写文件或字段 | 允许 |
| 已存在 settings 的 TOML 语法、schema_version 错误或版本不支持 | 警告，整份设置按第 7.4 节临时回退 | 可以原字节保留该文件并保存其他内容；设置修改必须先修复 | 禁止；修复、升级或显式移除该可选文件后再交付 |
| settings 的 TOML 和 schema 合法，但已知字段或关联约束错误 | 按第 7.4 节只回退错误字段、错误表或关联字段组；保留其他合法值 | 可以原字节保留原 settings；主动修改时须修复 | 禁止使用仅在内存中回退、尚未修复的设置交付 |
| 本次源码编辑引入非法控制 TOML | 保留编辑缓冲区 | 禁止提交该控制文件；必须提供恢复草稿 | 禁止使用未通过校验的变更 |
| 未编排 Markdown、未发现引用的资源 | 信息提示，不自动清理 | 保留 | 保留，用户明确选择删除除外 |
| 缺少 meta | 正常打开 | 允许 | 允许 |
| include_meta 为 false 且将剔除持久或未知 meta 数据 | 不改变打开行为 | 仍保留 meta，交付偏好不控制普通保存 | 按第 11 节列出剔除范围并确认；只影响交付副本 |
| 未知安全文件、未知字段、未知扩展 | 基础打开；必要时提示能力限制 | 保留，编辑限制见第 15 节 | 默认保留并注明未验证的扩展能力；meta 的显式筛选例外按第 11 节处理 |

严格交付不能省略容器安全、控制数据和已知引用检查；`validate_before_export = false` 不构成例外。网络状态不参与包内存在性判定。安全限额触发时必须终止相关处理并保留原文件。

修复流程必须在副本或独立恢复区工作，并说明哪些内容无法恢复。自动保存应尽量持久化全部已确认变更；存在非法控制文件缓冲区时，可以暂存恢复草稿，但不得将未包含全部变更的文件标记为“工程已完整保存”。

## 15. 兼容性策略

### 15.1 版本与降级

`contents.toml` 必须包含 `schema_version`；`settings.toml` 存在时也必须包含自己的 `schema_version`。两者分别校验，不能用一个文件的版本代替另一个。v1 的有效值仅为 TOML 整数 `1`，字符串 `"1"`、浮点数 `1.0`、零、负数和缺失均不合法。

| 情况 | contents.toml | settings.toml |
|------|---------------|---------------|
| 版本为 1 | 按 v1 解析 | 按 v1 解析；字段错误的回退范围见第 7.4 节 |
| 缺失版本、类型错误或非正整数 | 拒绝正常目录加载，可进入修复 | 保留原文件，警告并对整份设置临时回退 |
| 版本高于支持范围 | 提示升级，仅允许受限只读恢复，不得降写为 1 | 不解释该文件，临时使用模式预设与基础默认值；基础内容仍可打开，原字节保留，禁止编辑其未知结构 |
| 未来读取器遇到明确支持的旧版本 | 仅通过已定义的迁移规则转换 | 同左；不能只改版本号 |

v1 不存在已定义的更低正式 schema，不能把 `schema_version = 0` 自动当作旧版。临时默认值按第 7.3、7.4 节计算，不表示修复已经完成。

`mode` 是 default 的用途预设标识，不是版本号。未知 mode 仍按同一 v1 基础容器、目录和 Markdown 规则解析；显式通用设置继续按第 7 节解释，缺省字段使用 default 的基础默认值，并报告其附加约束和预设未被识别。普通保存必须保留其用途值和不透明数据；可能破坏未知约束或数据关联的编辑操作必须受限，必要时只读打开。用户可以显式选择切回 default，但不得静默代替用户切换。

新增 mode 只能定义 default 的用途子集。将来确需增加不兼容的目录项语义、正文模型或基础必需能力时，必须先修订 default 基础规范并升级相关 schema，不能仅分配新 mode 绕开基础规则。改变两字节前缀或 ZIP 边界属于新的容器协议，必须另行定义识别和迁移方式，不能用包内 schema 版本暗中改变 v1 外壳。

### 15.2 无损往返与扩展

1. 未修改文件的解压后内容必须逐字节保留；ZIP 的压缩结果、时间戳和条目排列不要求逐字节相同，但仍须满足 mimetype 首项等约束。
2. 普通保存必须保留未知普通文件、未知 TOML 字段和未知 meta 数据。默认交付也保留这些数据；只有用户显式选择的交付筛选可以按第 11 节剔除 meta。读取时“不解释”不等于保存时删除。
3. 修改已知 TOML 字段时，必须保留其他未知字段及其值；未知目录项扩展随稳定 ID 保留，不得按数组下标错误附着到其他条目。
4. 无法保证保留或关联一致性的实现必须限制相应编辑，或在明确说明损失后导出另一份用户选择的简化副本，不得静默覆盖原工程。
5. 扩展推荐使用 `[extensions.<命名空间>]` 或 `meta/<命名空间>/`；不得改变 v1 已定义字段含义。影响基础解析且无法忽略的扩展必须通过 schema 升级表达。

### 15.3 旧设计迁移

如果读取器遇到旧设计中的 `book.toml` / `theme.toml`：

1. 不应把它们视为 v1 合法必需文件。
2. 可尝试将 `book.toml.chapters` 迁移为 `contents.toml.entries`。
3. `theme.toml` 中的样式字段应迁移为 `settings.toml` 或应用级预设。
4. 缺少 contents 的旧设计文件只能通过显式导入或修复进入 v1。迁移前保留原件，迁移后执行校验；未识别的旧字段保留或报告，不得静默丢弃。

### 15.4 交付偏好的兼容

1. 已存在的 `export.include_meta = false` 继续表示交付副本不包含整个 meta，不能重解释成只剔除状态；本次剔除持久或未知数据的提示及确认要求仍按第 11 节执行。
2. 本版将 include_meta 的缺省值设为 true，并新增 `include_editor_state`，缺省为 false。读取时不把这两个默认值写回原文件；新建工程写入偏好时采用上述安全组合。
3. 旧文件若未写 include_meta，且没有其他明确的历史偏好记录，就无法推断旧应用曾采用的隐式默认值。此时按本版缺省解释，并在交付预检中明确列出将包含或剔除哪些 meta 数据，不静默猜测为 false。
4. 较旧实现可能不认识 include_editor_state，不能保证执行本版的状态筛选；需要确认筛选效果时应检查实际交付副本。仅因未知字段被保留，不能宣称已执行该字段的交付行为。

## 16. 安全要求

| 风险 | 要求 |
|------|------|
| Zip Slip 与链接逃逸 | 按第 12 节分别校验包内名称和引用；禁止实际访问工程根目录之外的文件。 |
| 解压资源耗尽 | 解压前限制条目数、声明大小和容器大小；解压过程中限制每个文件及累计实际输出、内存和处理时间。控制文件与资源使用同等保护，不得只相信 ZIP 声明大小。 |
| 路径混淆 | 拒绝重复项、文件目录冲突和非法编码；实际解包不得因大小写、Unicode 或宿主路径转换而覆盖其他目标。 |
| 非法或恶意媒体 | 识别扩展名与内容不符，预览使用隔离的解码环境；不能安全解码时停止预览，保留原始附件并报告。 |
| HTML / SVG 活动内容 | 原始 HTML 按第 8.3 节展示；SVG 只能以禁用脚本、外部请求和事件处理器的安全图像方式渲染，不能做到时只显示文件信息。 |
| 危险 URL | 包内引用须先校验；外部导航仅启用 HTTP、HTTPS 和由用户点击的 mailto 链接，其他协议默认禁用。禁止执行 javascript、vbscript、file 等协议；v1 基础预览不直接加载 data URL。HTTP(S) 媒体加载仍按第 8.3 节受用户控制。 |
| 损坏 ZIP | 返回可恢复错误；不得崩溃、静默截断或跳过失败文件后覆盖原工程。 |
| 未知扩展 | 作为不透明数据保留，不执行其中的代码或命令，不据此自动加载插件。 |

各实现必须公开或明确报告自身的容量限额；可以采用不同阈值，但不得将成功解压的一部分内容伪装为完整工程。遇到未知格式或不支持的预览能力时，优先提供源码或文件信息，不要求为了打开工程执行内容。

## 17. 最小合法 .mdk

一个最小合法 `.mdk` 文件必须包含两字节 mode 和以下两个包内文件。这里以 `00` 为例；`01`、`02` 也允许没有目录项的空工程：

```text
mode 文件头: "00"

zip payload:
├── mimetype
└── contents.toml
```

最小 `mimetype`：

```text
application/vnd.mardikor.mdk+zip
```

最小 `contents.toml`：

```toml
schema_version = 1
```

该最小文件没有目录项、Markdown 正文、资源、settings 和 meta。读取器必须以空工程方式打开。

## 18. 常见合法示例

### 18.1 正常 book 工程

```text
mode 文件头: "01"

zip payload:
├── mimetype
├── contents.toml
├── settings.toml
└── markdown/
    ├── 001.md
    └── chapter-two.md
```

```toml
schema_version = 1

[[entries]]
id = "01JZ8F8V7K9Y3M5P0Q2R6T1A4B"
path = "markdown/001.md"
position = "1"

[[entries]]
id = "01JZ8F92N6C4X8Q1V7W3D5E0K2"
path = "markdown/chapter-two.md"
position = "2"
```

### 18.2 正常 comic 工程

目录项指向普通 Markdown 文稿，文稿通过相对引用使用图片；图片本身不作为 entries 的直接目标。此例采用每篇一张图片，仅是创作选择；多图、图文混排和纯文字文稿同样合法。漫画模式的展示编排按第 3.2 节解释。

```text
mode 文件头: "02"

zip payload:
├── mimetype
├── contents.toml
├── settings.toml
├── markdown/
│   ├── 001.md
│   └── 002.md
└── resources/
    └── image/
        ├── 001.png
        └── 002.png
```

```toml
schema_version = 1

[[entries]]
id = "01JZ8F8V7K9Y3M5P0Q2R6T1A4B"
path = "markdown/001.md"
position = "1"

[[entries]]
id = "01JZ8F92N6C4X8Q1V7W3D5E0K2"
path = "markdown/002.md"
position = "2"
```

`markdown/001.md`：

```markdown
![第 1 页](../resources/image/001.png)
```

`markdown/002.md`：

```markdown
![第 2 页](../resources/image/002.png)
```

将上述工程的 mode 从 `02` 改为 `00` 后，整个 payload 无须变动，仍是合法的 default 工程。`01` 的书籍示例具有相同性质；回到 default 不需要合并、拆分或转换 Markdown。

## 19. v1 约束总结

| 项目 | v1 结论 |
|------|---------|
| 文件扩展名 | `.mdk` |
| 文件头 | 2 位 ASCII 十六进制 `mode` |
| 默认 mode | `00`，统一的 Markdown 基础工程 |
| 书籍 mode | `01`，default 的用途子集；只增加约定、限制和默认设置 |
| 漫画 mode | `02`，default 的用途子集；图文始终保存在 Markdown 中 |
| 模式切换 | 合法 book/comic 可仅改 mode 回到 default；正文、目录和资源无须转换 |
| payload | 两字节前缀之后的独立 ZIP；内部偏移量以 payload 起点为基准 |
| ZIP 支持范围 | 单卷、非 ZIP64、无 ZIP 加密；STORE / DEFLATE |
| MIME | `application/vnd.mardikor.mdk+zip` |
| 必需 TOML | `contents.toml` |
| 正常工程推荐 TOML | `settings.toml` |
| 已废弃 TOML | `book.toml`、`theme.toml` |
| `contents.toml` 职责 | 只控制目录 |
| `contents.toml.entries[]` 必需字段 | `id`、`path`、`position` |
| 目录项身份 | ID 非空且工程内唯一；多个条目可引用同一 Markdown 文件 |
| 目录层级 | `position` outline-path，最多 6 层；允许编号空缺及虚拟父分组，独立于正文标题 |
| Markdown 目录 | `markdown/` |
| 漫画预览 | 一个实际目录项对应一个文稿展示单元；单双页仅为视图排布，不改变 Markdown 模型 |
| 资源目录 | `resources/image/`、`resources/video/`、`resources/audio/`、`resources/font/`、`resources/other/` |
| `meta/` | 普通保存及默认交付保留持久和未知数据；显式交付筛选按第 11 节执行 |
| meta 交付默认值 | include_meta 为 true、include_editor_state 为 false；剔除持久或未知数据须明确确认 |
| 设置回退 | 语法或版本错误整体回退；单字段错误局部回退，关联约束按字段组回退；均不自动改写源文件 |
| 字号与页宽 | 有限正数；界面推荐范围不决定格式是否合法 |
| 路径 | 包内名称禁止点路径段；正文相对引用允许 `..`，解析结果不得逃逸根目录 |
| 普通保存 | 允许缺失引用的未完成工程；必须报告问题并可靠保留修改 |
| 严格交付 | 检查容器、控制数据及已知依赖；portable 展示依赖须在包内 |
| 可靠写入 | 临时文件校验后原子发布；失败保留原工程和待保存状态 |
| v1 导出目标 | 仅导出 `.mdk` |
| 其他格式转换 | 后续版本再考虑 |
| 源码模式 | 必须支持编辑 `.md`、`.toml` 等纯文本文件 |
| schema version | `1` |

## 附录 A. 编辑器实现建议（非强制）

1. 文件树可作为 contents 的可视化编辑界面；源码模式、文件树组件、按钮名称和布局不改变文件格式。
2. 实现可以实时更新目录，也可以对拖拽排序做防抖或批量更新。200 个 Markdown 文件可以作为性能调优起点，但不是格式阈值，也不要求用户必须点击“更新目录”。
3. 延迟提交时应显示待保存状态；工程保存和交付的一致快照要求仍按第 6.4、13 节执行。
4. 可重建的 UI 状态优先保存在本机；恢复草稿应与正常工程区分，不能在恢复失败时覆盖最后一次成功保存的文件。
5. 字号控件可默认提供 8–120 px 的常用范围，页宽控件可从 200 px 起提供常用选项；这些是界面建议，不得据此拒绝符合第 7 节的其他合法数值。渲染超限时提示限制、保留原值，并允许源码处理。
6. book/comic 可以使用不同的工具布局和预览入口，但必须保持同一套 Markdown 源码与内容；模式切换不应成为一次隐含的正文转换。

## 附录 B. 一致性验证建议

实现至少应覆盖以下情况，避免仅凭自身写出的文件能够重新打开就宣称符合规范：

| 用例 | 预期结果 |
|------|----------|
| 仅 mode、mimetype 和最小 contents | 作为空工程打开；不要求 settings、显式目录条目或 meta。 |
| 第 18.1、18.2 节样例 | 目录字段合法；书籍和漫画均使用基础 Markdown 文稿。 |
| 将合法 book/comic 的 mode 改为 00 | 原 payload 仍通过 default 基础校验，正文和目录数据不变，不要求转换。 |
| comic 文稿含多张图片、普通段落，或不含图片 | 保持 Markdown 原有语义；一个实际目录项仍是一个展示单元，不自动按图片拆页。 |
| comic 双页预览含虚拟分组、重复文件引用和奇数个条目 | 仅实际目录项参与配对；重复引用分别展示，末项单独显示，rtl 时一对中的前项在右。 |
| 重复 ID、重复 position、`01`、`1.0`、超过 6 层 | 拒绝提交目录；保留源码缓冲区。 |
| 仅有 `2.1`，以及两个不同 ID 引用同一个 path | 构建虚拟父分组，保留两个独立条目。 |
| `../resources/image/cover.png` 从 markdown 中引用 | 解析到工程内 resources；不因含 `..` 直接拒绝。 |
| 越界引用、编码后的越界路径、绝对 ZIP 路径 | 禁止访问包外；不安全 ZIP 路径不得正常打开或解包。 |
| 缺失正文或图片 | 允许基础打开和普通保存；严格交付失败。 |
| include_meta 为 true、include_editor_state 为 false | 保留批注和未知数据，仅剔除已识别的可重建状态。 |
| 旧工程显式设置 include_meta 为 false | 仍表示排除整个 meta；含持久或未知数据时须确认本次交付，源工程不受影响。 |
| meta 设置字段缺省 | 使用 true / false 的安全默认组合，不自动写回；预检明确实际交付范围。 |
| settings 缺失、非法、未来版本 | 分别验证默认解释、无损降级及交付限制；不得自动覆盖为默认设置。 |
| settings 中 font_size 非法，但颜色和页宽合法 | 只回退字号；其他合法显式值生效，原文件不变，严格交付要求修复。 |
| 左右边距之和不小于页宽 | 仅对 page_width、margin_left、margin_right 进行关联回退；其他设置不受影响。 |
| font_size 为 160，page_width 为 100，左右边距各 10 | 数值及几何约束合法；不能因超出界面推荐范围而拒绝工程。 |
| 物理首项与中央目录排序不同 | 以本地文件头物理位置判定 mimetype 首项。 |
| 非法 ZIP 方法、重复条目、大小或 CRC 错误 | 明确拒绝，不产生部分内容覆盖原文件。 |
| 临时文件写入、校验或发布失败 | 原工程保持可读；待保存标记和恢复数据仍可用。 |

本规范是实现依据，既有应用的功能核对或测试记录不能代替对本次修订要求的验证。
